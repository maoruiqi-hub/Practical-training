# 能力点映射第一版联调报告

> 联调日期：2026-09-01  
> 环境：本地 Vue 开发服务器、Spring Boot、服务器 KingbaseES 测试库  
> 结论：前后端主通路通过，可进入真实课程试运行。

## 1. 验证范围

- 教师登录并进入能力图谱页面；
- 创建课程真能力；
- 维护“相关 / 不相关 / 不确定”关系；
- 为真能力配置观测任务；
- 生成候选矩阵和校准报告；
- 发布候选版本并切换正式矩阵；
- 学生端读取已发布矩阵并聚合真能力分数；
- 未登录写请求和重复发布请求的权限/状态校验；
- 前端接口单元测试、生产构建和后端测试。

## 2. 实测结果

使用“Python 程序设计”课程完成联调，建立了以下真能力：

- 程序设计与逻辑建模；
- 数据处理与问题求解；
- 软件构造与调试。

发布后，教师端能够显示每个假能力点对应的关系状态和归一化强度。同一假能力点下所有“相关”强度之和为 1（六位小数舍入时允许出现 `0.999999`）。学生端数据中心能够显示三项真能力、有效来源覆盖数和聚合分数。

候选版本发布前不影响当前正式矩阵；发布后教师端和学生端均读取新版本。重复发布同一候选版本会被拒绝，未登录关系写入会被拒绝。

## 3. 联调中发现并修复的问题

### 3.1 初始强度未整行归一化

连续把多个真能力标记为“相关”时，旧关系没有同步重新均分，可能导致同一假能力点的强度和大于 1。现已改为每次教师修改关系后，对当前已发布版本的整行重新应用均匀先验，并清空旧行为证据，等待下一次候选校准。

### 3.2 校准报告显示内部编号

教师端校准报告原先显示能力点 ID 和真能力 UUID。现已改为显示教师可理解的能力名称。

## 4. 当前数据限制

测试库虽然有 15 名学生的观测任务成绩，但当前只有 1 名学生在旧 `competency_score` 表中具备对应假能力点分数，因此本次校准报告正确显示“共同样本 1、样本不足、置信度有限”。

这说明接口、划分和报告通路工作正常，但当前数据不足以验证强度学习效果。正式试运行前需要让学生能力评估流程持续写入更多学生的假能力点分数；样本不足时，系统保持均匀先验，不应把当前相关度解释为统计结论。
