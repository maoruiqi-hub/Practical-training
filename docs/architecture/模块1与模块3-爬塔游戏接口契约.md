# 模块 1、模块 3 与爬塔游戏接口契约

本文件落实 `specs/模块接口与协作规范.md` 第 4、6、14 节。模块 4 是唯一的游戏引擎；模块 1 和模块 3 只维护业务事实与发送事件，绝不自行计算 HP、ATK、DEF、EXP、金币或奖励。

## 标识与当前兼容性

规范目标是 UUID v4。当前项目历史表使用自增数字 ID，并以 Java `String` 传递；本次新增接口统一把它们视为不透明字符串。全项目 UUID 迁移应统一完成，不能由单个模块单独更改。

## 模块 1：塔地图内容接口

所有路径还需加全局前缀 `/practical-training`。

| 方法与路径 | 用途 |
|---|---|
| `GET /api/courses/{courseId}` | 课程信息 |
| `GET /api/courses/{courseId}/structure` | 知识点树，塔的结构来源 |
| `GET /api/knowledge-points?course_id={courseId}` | 知识点列表 |
| `GET /api/knowledge-points/{knowledgePointId}/prerequisites` | 前置链，供模块 4 计算可达性与 DEF |
| `GET /api/knowledge-graph?course_id={courseId}` | 图谱节点与边 |
| `GET /api/ability-map?course_id={courseId}` | 能力图谱 |
| `GET /api/courses/{courseId}/config` | `{ "game_mode_enabled": false }` |
| `PUT /api/courses/{courseId}/config` | 教师开启/关闭游戏模式；body：`{ "gameModeEnabled": true }` |
| `PUT /api/knowledge-points/{knowledgePointId}/floor-status` | 教师/模块 4 更新楼层状态；body：`{ "studentNo":"…", "status":"locked|available|cleared|weak" }` |

模块 4 在同一进程内应优先调用：

```java
knowledgePointService.getPrerequisiteChain(knowledgePointId);
floorStatusService.updateStatus(studentNo, courseCode, knowledgePointId, status);
courseGameConfigService.isGameModeEnabled(courseCode);
```

## 模块 3：测评数据接口

| 方法与路径 | 用途 |
|---|---|
| `GET /api/questions?course_id=&knowledge_point_id=&difficulty=` | 题库查询（教师） |
| `POST /api/questions/{questionId}/link-kp` | 按知识点 ID 关联题目；body：`{ "knowledgePointId":"…" }` |
| `GET /api/exams?course_id=` | 试卷列表 |
| `GET /api/exams/{examId}` | 试卷详情与题目快照 |
| `GET /api/students/{studentId}/scores?course_id=` | 学生成绩记录 |
| `GET /api/students/{studentId}/mistakes?course_id=&knowledge_point_id=` | 学生错题 |
| `GET /api/courses/{courseId}/mistake-stats` | 按知识点与题型汇总错题率 |
| `GET /api/exams/{examId}/scores` | 试卷全体成绩 |

客观题提交后，模块 3 会通过 `AssessmentMasteryService` 将该学生、课程、知识点的累计正确率写入模块 1 的 `KnowledgeMastery`。模块 3 不直接写模块 1 的表。

## 模块 3 → 模块 4 游戏事件

游戏模式关闭时不发事件。开启后，模块 3 发布 Spring 进程内 `TowerGameEvent`；未来模块 4 实现 `GameEventPublisher` 或监听该事件即可接收。

| 事件 | 触发条件 | payload |
|---|---|---|
| `answer_correct` | 客观题答对 | `question_id`、`knowledge_point_id`、`difficulty`、`is_first_attempt`、`attempt_count` |
| `answer_wrong` | 客观题答错 | 同上 |
| `floor_cleared` | 同次提交中某知识点正确率 ≥ 85% | `knowledge_point_id`、`correct_rate`、`is_perfect`、`time_total_ms` |
| `floor_failed` | 同次提交中某知识点正确率 < 40% | `knowledge_point_id`、`correct_rate`、`is_perfect`、`time_total_ms` |

事件通用字段：`eventId`、`studentId`、`courseId`、`sourceModule=module3_assessment`、`sourceId=submissionId`、`occurredAt`。模块 4 应按 `eventId` 幂等处理。

## 尚待模块 4 接入的职责

1. 消费事件，维护 HP、ATK、DEF、EXP、等级、金币、精力和成就。
2. 按事件结果调用模块 1 的楼层状态服务，形成 `locked / available / cleared / weak` 塔地图。
3. 提供规范规定的 `GET /api/students/{studentId}/tower-map?course_id=`。
4. 处理 Boss、精英、补给、提示和遗物事件；这些都是模块 4 的规则，不应复制到模块 1 或模块 3。
