# 前端入口缺口与建设优先级

> 更新时间：2026-08-20  
> 适用分支：`codex-tower-map-path-selection`

## 1. 结论先行

当前前端不是“功能完全没有”，而是“页面和接口已经不少，但入口层级不完整”。

学生端已经形成了核心闭环：

```text
塔地图 → 活动挑战 → 任务列表 → 任务详情/提交 → 在线测验或作业提交
```

接下来最重要的不是继续增加零散页面，而是把学生常用功能都放回游戏化主界面中，并保证学生第一次进入系统时能找到：

1. 当前课程和课程切换
2. 待完成作业和即将截止任务
3. 课程资源与知识点学习
4. 错题复习、学习进度和能力变化

教师端则需要把目前分散在课程详情、学生画像和任务页面中的操作，整理成清晰的工作台入口。

## 2. 优先级定义

| 优先级 | 含义 | 判断标准 |
| --- | --- | --- |
| P0 | 必须优先补齐 | 影响核心学习/教学闭环，用户无法正常完成主要任务 |
| P1 | 第二阶段建设 | 功能已有但难发现，或影响日常使用效率 |
| P2 | 后续增强 | 分析、配置、AI 等高级能力，短期不阻断主流程 |

## 3. P0：必须优先补齐的入口

### P0-1 学生课程选择与切换入口

现状：

- 学生访问 `/courses` 会被重定向到塔地图的宝箱房间。
- 学生端没有一个稳定的“我的课程 / 切换课程”界面。
- 塔地图中的课程上下文主要依赖 `courseId` 查询参数或本地存储，默认值为 `1`，新用户容易进入错误课程。

建议：

- 在塔地图顶部 HUD 增加当前课程名称和课程切换按钮。
- 点击后打开游戏化课程选择面板，而不是跳回传统课程列表。
- 选择课程后重新加载塔地图、作业、资源、知识图谱和学习数据。
- 无课程时提供“加入课程 / 等待教师分配”的明确空状态。

### P0-2 学生待办任务提醒入口

现状：

- “活动挑战”已经可以进入当前课程的任务大厅。
- 但塔地图目前不能直接显示待完成数量、即将截止任务或逾期任务。
- 学生需要主动点击入口才能发现作业。

建议：

- 在“活动挑战”入口增加待完成数量徽标。
- 在塔地图 HUD 或活动挑战入口附近显示最近截止任务。
- 将任务分为“待完成、待批改、已完成、已逾期”。
- 入口仍保持游戏化，不增加传统后台式侧边栏。

### P0-3 学生任务完成闭环的统一详情页

现状：

- 任务列表、任务提交页、在线测验页已经存在。
- 普通作业提交页和任务详情页正在统一为塔地图主题。
- 在线测验页面仍需要继续检查是否与新主题一致。

建议：

- 普通作业、在线测验、资料阅读、视频学习统一使用“挑战详情”结构。
- 详情页固定展示：任务说明、截止时间、奖励/分值、提交次数、完成状态。
- 完成后提供“返回活动挑战”和“返回塔地图”两个明确出口。
- 任务完成后刷新活动挑战徽标和塔地图任务状态。

## 4. P1：已有功能但入口不完整

### P1-1 学生课程资源入口

现状：

- 课程资源页面和资源预览页面已存在。
- 宝箱房间、休息房间可以间接访问课程资源。
- 学生不能从塔地图直接查看“本课程全部资源”。

建议：

- 在塔地图增加“知识补给 / 课程资源”入口，或放入 HUD 的学习菜单。
- 资源按课时、知识点、资源类型分组。
- 资源学习完成后回写学习记录，并在塔地图形成奖励或进度反馈。

### P1-2 学生知识图谱与知识点详情入口

现状：

- 知识图谱、知识点详情和课时详情页面已经存在。
- 这些页面主要依赖传统课程详情页面进入。
- 学生端课程列表被重定向后，入口变得不明显。

建议：

- 从塔地图节点详情增加“查看知识点”入口。
- 从“活动挑战”任务卡片进入关联知识点。
- 知识图谱作为塔地图的“路线情报”入口，而不是独立后台页面。

### P1-3 学生错题本与复习入口

现状：

- 错题本页面和错题统计接口已经存在。
- 商店、休息点中已经有错题卡和复习相关交互。
- 学生端传统导航被隐藏，错题本缺少稳定的直接入口。

建议：

- 在塔地图中保留“错题商店 / 复习营地”作为主要入口。
- 增加一个可见的错题数量提示。
- 错题卡点击后进入“错因、知识点、再练一道”的复习流程。
- 传统错题本页面作为完整查看页保留，但不作为主要产品入口。

### P1-4 学生学习进度与成长反馈入口

现状：

- 学习进度、成绩统计、学情分析、学生画像页面均已存在。
- 学生访问部分传统路径会被转为塔地图房间，但目前缺少统一的成长入口。

建议：

- 在 HUD 增加“成长档案”入口。
- 统一展示通关进度、掌握度变化、作业完成率、错题下降趋势和能力成长。
- 统计数据使用游戏化表达，例如章节徽章、经验、能力雷达和成长事件。

## 5. P1：教师日常教学入口

### P1-1 教师任务发布与分配中心

现状：

- 教师可以在课程详情的“学习任务”页发布任务。
- 教师可以在学生画像页面分配任务。
- 任务发布和任务分配分散在不同页面，没有统一的任务工作台。

建议：

- 在教师侧边栏增加“任务中心”。
- 统一处理：发布任务、选择学生/班级、设置截止时间、查看完成情况、催交和关闭任务。
- 课程详情保留快捷入口，但不再承担全部任务管理职责。

### P1-2 教师任务完成情况入口

现状：

- 任务提交列表和成绩统计接口存在。
- 教师需要进入具体任务或学生画像才能查看相关结果。

建议：

- 任务中心增加“待批改、未提交、逾期、低分”四类队列。
- 直接进入学生提交详情和 AI 评阅。
- 对同一课程支持按班级、任务、截止时间筛选。

### P1-3 教师课程内容运营入口

现状：

- 课时、课程资源、知识图谱、能力图谱均有页面。
- 入口主要集中在课程详情内部，层级较深。

建议：

- 在教师工作台提供“课程内容”入口。
- 统一管理课时、资源、知识点、知识关系和能力点。
- 明确区分“内容建设”和“学生学习数据”。

## 6. P2：后续增强入口

### P2-1 考试与组卷中心

现状：

- 题库管理、试卷生成和试卷绑定接口已经存在。
- 部分组卷操作嵌在课程详情发布任务弹窗中。
- 没有独立的考试/组卷入口。

建议：

- 增加教师端“考试中心”。
- 支持组卷、预览、绑定作业、发布、批次管理和成绩查看。

### P2-2 AI 知识图谱构建入口

现状：

- 后端已有知识抽取、候选节点确认和知识图谱相关接口。
- 前端有知识图谱展示，但缺少清晰的“从资料生成图谱”工作流入口。

建议：

- 在教师课程内容中心增加“AI 构建知识图谱”。
- 展示抽取候选、接受/拒绝、关系校正和生成结果。

### P2-3 管理员系统配置入口

现状：

- 学生、教师、课程、题库管理入口已有。
- 课程模式、权限、数据库/部署配置不属于当前学生学习闭环。

建议：

- 后续独立增加系统设置、角色权限、课程开关和运行状态页。
- 不要把这些配置放入游戏化学生界面。

## 7. 当前页面入口盘点

| 功能 | 页面/路由 | 当前入口情况 | 优先级 |
| --- | --- | --- | --- |
| 塔地图 | `/tower-map` | 学生主入口 | 已有 |
| 活动挑战 | `/task/:courseCode` | 已从塔地图接入 | 已有，需继续完善徽标 |
| 普通作业提交 | `/task/:courseCode/submit/:taskNo` | 活动挑战进入 | 已有，已主题化 |
| 在线测验 | `/quiz/take/:taskNo` | 活动挑战进入 | 已有，需主题统一 |
| 课程资源 | `/course/:code/resources` | 课程详情/房间间接进入 | P1 |
| 知识图谱 | `/course/:code/knowledge-graph` | 课程详情进入 | P1 |
| 错题本 | `/wrong-book` | 页面存在，学生主导航被隐藏 | P1 |
| 学习进度 | `/progress` | 页面存在，学生路径转为房间 | P1 |
| 学生画像 | `/profile` | 页面存在，学生路径转为休息房间 | P1 |
| 教师发布任务 | `/course/:code` | 课程详情“学习任务”页 | P1 |
| 教师分配任务 | `/teacher/student-profiles` | 学生画像页内入口 | P1 |
| 教师提交复核 | `/task/:courseCode/submit/:taskNo` | 任务页内入口 | P1 |
| 考试组卷 | 课程详情任务弹窗 | 没有独立入口 | P2 |
| AI 知识抽取 | 后端接口已有 | 缺少完整前端工作流 | P2 |

## 8. 推荐实施顺序

### 第一阶段：学生核心闭环

1. 增加塔地图当前课程切换。
2. 给“活动挑战”增加待办数量和截止提醒。
3. 统一在线测验页与普通作业提交页主题。
4. 完成任务完成后的状态刷新和返回路径。

### 第二阶段：学习资料与成长入口

1. 增加课程资源入口。
2. 增加知识点/知识图谱入口。
3. 增加错题数量、复习营地和成长档案入口。

### 第三阶段：教师工作台

1. 任务中心。
2. 待批改和未提交队列。
3. 课程内容运营中心。

### 第四阶段：高级教学能力

1. 考试与组卷中心。
2. AI 知识图谱构建流程。
3. 系统管理和权限配置。

## 9. 设计原则

- 学生端保持游戏化主界面，数据、错题本、资源和作业都是游戏世界中的入口。
- 不采用“传统后台壳 + 中间一个爬塔按钮”的结构。
- 一个功能可以有完整页面，但必须从塔地图、HUD、房间或节点详情中被发现。
- 学生端优先展示下一步行动，教师端优先展示待处理事项。
- 新增入口必须说明当前课程、任务状态和返回路径，避免依赖手动输入 URL。
