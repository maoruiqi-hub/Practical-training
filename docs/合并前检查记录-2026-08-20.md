# 合并前检查记录（2026-08-20）

## 检查范围

本次针对当前分支进行合并前检查，重点关注学生端真实学习链路、后端数据一致性、权限边界和演示数据兜底。推荐结果不自动驱动关卡跳转属于当前设计取舍，本次不作为缺陷处理。

## 已处理

### 删除后端虚假关卡兜底

`TowerRunServiceImpl` 在课程没有知识点时，原先会生成 `demo-kp / 课程基础挑战`，导致课程数据缺失时仍显示可玩的虚假路线。

现已改为：

- 没有知识点时不生成虚假节点；
- 返回“课程尚未配置知识点，无法生成学习路线”；
- 前端显示明确错误状态。

## 检查中发现的问题及处理状态

### 1. ProfileApiController 的学生身份边界不够严格

原先 `/api/students/{studentId}/**` 部分接口主要判断是否登录，没有统一校验 `studentId` 是否属于当前学生。

现已处理：

- 学生只能访问和操作自己的 `studentId`；
- 管理员保留运维访问能力；
- 画像、爬塔、能力、成长值、成就、推荐和题包接口统一使用本人校验；
- `game-event` 已补充会话校验，不能再伪造其他学生事件。

### 2. 登录响应携带 Student 实体

已处理：

- 新增非实体的 `LoginResponse` DTO；
- 学生和教师登录接口均改为返回脱敏 DTO；
- Session 仍保存完整实体，现有认证和业务逻辑不受影响；
- 登录响应不再包含密码字段。

- 前端生产构建：通过。

- 前端固定地图、虚构宝箱奖励和本地战斗结算兜底已移除。
