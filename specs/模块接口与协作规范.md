# 模块接口与协作规范

> **文档定位**：本文档是5个模块之间的**接口契约**——每个模块"对外暴露什么，需要他人提供什么"。
> 在 `specs/项目需求.md`（应该建什么）确定后，本文档定义模块间**怎么配合**，是每个人独立开发的上手指南。

---

## 一、架构总览

```
┌──────────────────────────────────────────────────────────────┐
│  Frontend                                                     │
│  教师端 · 学生端                                              │
└──────────────────────────┬───────────────────────────────────┘
                           │ RESTful API（统一网关）
                           │
┌──────────────────────────┴───────────────────────────────────┐
│  Backend（单体后端，模块化包结构）                              │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────┐│
│  │ 模块1    │ │ 模块2    │ │ 模块3    │ │ 模块4    │ │模块5 ││
│  │ 课程内容  │ │ 学习任务  │ │ 测评评价  │ │ 学生画像  │ │学情  ││
│  │ 知识组织  │ │ 过程跟踪  │ │ 成果评价  │ │ 个性化    │ │分析  ││
│  └─────┬────┘ └─────┬────┘ └─────┬────┘ └─────┬────┘ └───┬──┘│
│        └─────────────┴────────────┴────────────┴──────────┘  │
│                              │                                │
└──────────────────────────────┼────────────────────────────────┘
                               │
┌──────────────────────────────┴───────────────────────────────────┐
│  agentic/（独立 AI 服务，非第6模块）                                │
│  知识图谱生成 · 智能批改 · 学习推荐 · 风险预警 · 问题聚类 · AI对话   │
└──────────────────────────────────────────────────────────────────┘
```

**关键约束**：

| 约束 | 说明 |
|------|------|
| 后端架构 | Spring Boot 3 + Java 17 + Maven，单体应用 + 模块化包结构（每个模块一个 package），非微服务 |
| 前端架构 | Vue 3 + Element Plus + ECharts + Axios（教师端 + 学生端） |
| 数据库 | 金仓（KingbaseES）关系型数据库 + 向量数据库（产品待定） |
| 持久层 | MyBatis-Plus 3.5 |
| 模块间通信 | 同一进程内的 Service 方法调用，不是 HTTP |
| AI 调用 | 所有 LLM 调用统一走 `agentic/` 服务，各模块只负责组装 prompt 和消费结果 |
| 数据归属 | 每个数据表只有一个模块负责写入，其他模块只读或通过接口查询 |
| 鸿蒙端 | 后续阶段以独立元服务形态适配，不嵌入核心后端 |

> **技术栈明细**：后端 `Spring Boot 3.5.15` / `Java 17` / `Maven` / `MyBatis-Plus 3.5.15` / `Lombok`，前端 `Vue 3` / `Element Plus 2.14` / `ECharts 6` / `Pinia 3` / `Axios`，数据库 `金仓 KingbaseES`（兼容 MySQL 驱动开发期可用 MySQL 过渡）。鸿蒙端作为独立子项目后续开发。

## 三、共享标识符（Shared ID）规范

所有模块间通过 ID 引用对方的数据，不直接访问对方的数据表。

```
  模块1 产生             模块2 产生             模块3 产生             模块4 产生
  ─────────             ─────────             ─────────             ─────────
  CourseID              TaskID                QuestionID            StudentID
  ResourceID            SubmissionID          ExamID
  KnowledgePointID      LearningLogID         AnswerID
  KnowledgeRelationID                          GradeResultID
  AbilityPointID

  模块5 产生
  ─────────
  ClassID
  RiskAlertID
  ClusterID
  AnalysisReportID
```

**ID 格式约定**：所有 ID 使用 UUID v4 字符串（如 `"a1b2c3d4-..."`），由各模块生成，全局唯一。

## 四、模块1 详细接口：课程内容与知识组织

### 4.1 核心实体

| 实体 | 说明 | 关键字段 |
|------|------|---------|
| `Course` | 课程（当前 = Python编程与数据分析基础） | id, name, description, credits, hours |
| `Resource` | 课程资源（PPT/PDF/视频等） | id, course_id, type, title, file_url |
| `KnowledgePoint` | 知识点节点（塔的一层） | id, course_id, name, description, level, parent_type |
| `KnowledgeRelation` | 知识点关系（前置依赖等） | id, from_kp_id, to_kp_id, relation_type |
| `AbilityPoint` | 能力点（课程能力图谱节点） | id, course_id, name, description |

### 4.2 对外暴露接口

```
模块1 对外暴露（其他模块可以调用）：
──────────────────────────────────

# -- 课程 --
GET    /api/courses/{id}               → 返回课程基本信息
GET    /api/courses/{id}/structure     → 返回课程完整知识结构（知识点树）

# -- 知识点 --
GET    /api/knowledge-points/{id}      → 返回知识点详情
GET    /api/knowledge-points           → 按课程查询知识点列表
         ?course_id={id}
GET    /api/knowledge-graph            → 返回知识图谱（节点+边）
         ?course_id={id}
GET    /api/knowledge-points/{id}/prerequisites
                                       → 返回某知识点的所有前置知识点
GET    /api/ability-map                → 返回课程能力图谱
         ?course_id={id}

# -- 高频薄弱（供模块5消费） --
GET    /api/courses/{id}/weak-points   → 返回高频薄弱知识点排名
```

### 4.3 自身完整接口（含增删改）

```
# -- 课程（教师端） --
POST   /api/courses                    → 创建课程
PUT    /api/courses/{id}               → 修改课程

# -- 资源（教师端） --
POST   /api/courses/{id}/resources     → 上传资源
GET    /api/resources/{id}/preview     → 资源在线预览
DELETE /api/resources/{id}             → 删除资源

# -- 知识点（教师端） --
POST   /api/courses/{id}/knowledge-points/extract
                                       → 自动提取知识点（→ agentic）
POST   /api/knowledge-points           → 手动创建知识点
PUT    /api/knowledge-points/{id}      → 修改知识点
DELETE /api/knowledge-points/{id}      → 删除知识点
POST   /api/knowledge-relations        → 创建知识点关系
DELETE /api/knowledge-relations/{id}   → 删除知识点关系

# -- 智能讲解/问答（学生端） --
POST   /api/knowledge-points/{id}/explain
                                       → PPT知识点智能讲解（→ agentic）
POST   /api/knowledge-points/{id}/qa   → 知识点问答（→ agentic）

# -- 能力图谱（教师端） --
POST   /api/ability-map/generate       → 生成课程能力图谱（→ agentic）
PUT    /api/ability-points/{id}        → 编辑能力点
```

### 4.4 对外提供的数据查询方法（模块间调用）

```java
// 模块1 在代码中提供这些 Service 方法，供其他模块直接调用（非 HTTP）：

// 模块2/3/4/5 都需要知道课程基本信息
CourseInfo getCourseInfo(String courseId);

// 模块3 关联试题到知识点时需要
List<KnowledgePoint> getKnowledgePointsByCourse(String courseId);

// 模块4 计算前置知识掌握度（DEF）时需要
List<KnowledgePoint> getPrerequisiteChain(String kpId);

// 模块4 更新能力评分时需要
List<AbilityPoint> getAbilityMap(String courseId);
```

### 4.5 依赖

| 依赖方 | 需要什么 | 数据从哪里来 |
|--------|---------|-------------|
| agentic | 课程大纲/教材文本 → 输出知识点列表+依赖关系 | LLM |
| 无模块间依赖（模块1是上游起点） | — | — |

## 五、模块2 详细接口：学习任务与过程跟踪

### 5.1 核心实体

| 实体 | 说明 | 关键字段 |
|------|------|---------|
| `Task` | 学习任务 | id, course_id, knowledge_point_id（可选）, type, title, description, deadline, submit_type, created_by |
| `Submission` | 学生提交 | id, task_id, student_id, content, files, submit_time, status |
| `LearningLog` | 学习行为日志 | id, student_id, task_id, resource_id, action_type, duration, detail, timestamp |

### 5.2 对外暴露接口

```
模块2 对外暴露：
────────────────

# -- 任务查询 --
GET    /api/tasks                       → 任务列表
         ?course_id={id}&student_id={id}
GET    /api/tasks/{id}                  → 任务详情

# -- 提交查询（供模块3打分、模块5查看） --
GET    /api/tasks/{id}/submissions      → 某任务的所有提交
GET    /api/students/{id}/submissions   → 某学生的所有提交
         ?course_id={id}

# -- 学习日志（供模块4计算画像、模块5分析） --
GET    /api/learning-logs               → 查询学习行为日志
         ?student_id={id}
         &course_id={id}
         &action_type={type}            # video_play, ppt_view, answer, code_submit...
         &start_time={}&end_time={}

# -- 进度统计 --
GET    /api/students/{id}/progress      → 学生整体学习进度
         ?course_id={id}
GET    /api/tasks/{id}/stats            → 任务完成统计
```

### 5.3 自身完整接口

```
# -- 任务管理（教师端） --
POST   /api/tasks                       → 发布任务
PUT    /api/tasks/{id}                  → 修改任务
DELETE /api/tasks/{id}                  → 删除任务

# -- 任务提交（学生端） --
POST   /api/tasks/{id}/submit           → 学生提交任务
PUT    /api/submissions/{id}            → 修改提交（截止前）

# -- 行为日志（后端自动采集，前端调用） --
POST   /api/learning-logs               → 记录一条学习行为
         body: {
           student_id, task_id, resource_id, knowledge_point_id,
           action_type, duration_ms, detail_json
         }
```

### 5.4 对外提供的数据查询方法

```java
// 模块3 批改时查询，模块5 分析完成情况时查询
List<Submission> getStudentSubmissions(String studentId, String courseId);

// 模块4 计算画像时按类型和时间范围拉取日志
List<LearningLog> getStudentLogs(String studentId, String courseId,
        List<String> actionTypes, LocalDateTime start, LocalDateTime end);

// 模块5 查看全局任务完成情况
TaskCompletionStats getTaskCompletionStats(String courseId);

// 模块4/5 获取学生学习进度快照
StudentProgress getStudentProgress(String studentId, String courseId);
```

### 5.5 依赖

| 依赖方 | 需要什么 | 说明 |
|--------|---------|------|
| 模块1 | CourseID, KnowledgePointID | 任务需要关联课程和知识点 |
| 模块4 | StudentID | 学生身份由模块4管理 |

## 六、模块3 详细接口：测评与成果评价

### 6.1 核心实体

| 实体 | 说明 | 关键字段 |
|------|------|---------|
| `Question` | 试题 | id, course_id, knowledge_point_id（关联模块1）, type, content, answer, difficulty, options |
| `Exam` | 试卷 | id, course_id, title, question_ids[], generate_type, total_score, time_limit |
| `Answer` | 学生作答 | id, exam_id, question_id, student_id, answer_content, is_correct, score |
| `GradeResult` | 评价结果 | id, target_id（submission或answer）, target_type, score, feedback, graded_by（auto/manual/ai） |

### 6.2 对外暴露接口

```
模块3 对外暴露：
────────────────

# -- 试题查询 --
GET    /api/questions                   → 题库列表
         ?course_id={id}&knowledge_point_id={id}&difficulty={level}

# -- 试卷查询 --
GET    /api/exams/{id}                  → 试卷详情（含试题列表）
GET    /api/exams                       → 试卷列表
         ?course_id={id}

# -- 成绩查询（供模块4画像、模块5分析） --
GET    /api/exams/{id}/scores           → 某次考试的全体成绩
GET    /api/students/{id}/scores        → 某学生的所有成绩
         ?course_id={id}

# -- 错题分析（供模块4推荐、模块5共性问题） --
GET    /api/students/{id}/mistakes      → 学生错题列表
         ?course_id={id}&knowledge_point_id={id}
GET    /api/courses/{id}/mistake-stats  → 课程错题统计（按知识点/题型分组）
```

### 6.3 自身完整接口

```
# -- 题库管理（教师端） --
POST   /api/questions                   → 创建试题
PUT    /api/questions/{id}              → 修改试题
DELETE /api/questions/{id}              → 删除试题
POST   /api/questions/import            → 批量导入试题
POST   /api/questions/{id}/link-kp      → 关联知识点

# -- 组卷（教师端） --
POST   /api/exams/generate              → 智能组卷
         body: {
           course_id, question_count, difficulty_mix,
           knowledge_point_ids[], generate_type  # random / by_kp / by_difficulty
         }

# -- 答题（学生端） --
POST   /api/exams/{id}/submit           → 提交试卷答案
         body: { answers: [{question_id, answer_content}, ...] }

# -- 智能批改（→ agentic） --
POST   /api/submissions/{id}/grade      → 对学生提交进行AI评价
         body: { submission_type: "report"|"essay"|"short_answer" }
         # 返回: GradeResult { score, feedback, suggestions }

# -- 重批 --
PUT    /api/grade-results/{id}          → 教师手动调整分数/反馈
```

### 6.4 对外提供的数据查询方法

```java
// 模块4 计算能力评分时需要，模块5 成绩报表时需要
List<ScoreRecord> getStudentScores(String studentId, String courseId);

// 模块4 推荐错题相关练习时需要
List<MistakeRecord> getStudentMistakes(String studentId, String courseId);

// 模块5 共性问题聚类时需要
ClassMistakeStats getClassMistakeStats(String courseId);

// 模块5 某次考试的成绩分布
List<ScoreRecord> getExamScores(String examId);
```

### 6.5 依赖

| 依赖方 | 需要什么 | 说明 |
|--------|---------|------|
| 模块1 | KnowledgePointID | 试题必须关联知识点 |
| 模块2 | SubmissionID | 评价的是学生提交的成果 |
| 模块4 | StudentID | 成绩归属学生 |
| agentic | 学生提交内容 + 评分标准 | 智能批改需要 LLM 评分 |

## 七、模块4 详细接口：学生画像与个性化学习


## 八、模块5 详细接口：学情分析与教学决策

```
# -- 班级管理（管理员/教师） --
POST   /api/classes                     → 创建班级
PUT    /api/classes/{id}                → 修改班级信息

# -- 成绩查看（教师端） --
GET    /api/classes/{id}/scores         → 班级成绩总览
GET    /api/classes/{id}/score-trends   → 成绩趋势图表数据

POST   /api/students/{id}/intervention  → 生成干预建议

# -- 反馈汇总 --

# -- 共性问题聚类（→ agentic） --

                                       → 执行共性问题聚类分析
         # 返回: ClusterResult[] 列表

                                       → 生成教学调整建议

# -- 报表导出 --

```

## 九、agentic 服务（公共 AI 能力层）

> agentic 是独立服务，不是第6个业务模块。它只提供 LLM 推理能力，不持有业务数据表。

### 9.1 服务接口

```
POST   /api/agent/knowledge-extract     → 知识图谱自动提取
         body: { course_id, materials: [{type, content}] }
         returns: { knowledge_points: [{name, description, level, prerequisites[]}] }

POST   /api/agent/diagnostic-test       → 入学诊断评测
         body: { student_id, course_id, knowledge_map }
         returns: { recommended_start_kp, skipped_kp[], weak_kp[] }

POST   /api/agent/chat                  → AI 对话（知识点讲解/问答）
         body: { student_id, knowledge_point_id, context, question }
         returns: { answer, follow_up_questions[] }

POST   /api/agent/grade                 → 智能批改
         body: { submission_id, submission_type,  content, rubric }
         returns: { score, feedback, improvement_suggestions[] }

POST   /api/agent/recommend             → 个性化推荐
         body: { student_id, course_id, profile, recommendation_types[] }
         returns: { recommendations: [{type, target_id, reason, priority}] }

POST   /api/agent/risk-detect           → 学习风险检测
         body: { student_id, learning_data, thresholds }
         returns: { risk_level, risk_types[], detail }

POST   /api/agent/cluster-problems      → 共性问题聚类
         body: { class_id, course_id, mistakes[], feedbacks[], questions[] }
         returns: { clusters: [{topic, count, typical_cases[], severity}] }

POST   /api/agent/teaching-suggestions  → 教学建议生成
         body: { class_id, course_id, weak_points[], clusters[], progress_data }
         returns: { suggestions: [{content, target, urgency}] }
```

### 9.2 调用关系总览

```
模块1 ──→ agentic: 知识提取、PPT讲解、知识点问答
模块3 ──→ agentic: 智能批改
模块4 ──→ agentic: 个性化推荐
模块5 ──→ agentic: 风险检测、问题聚类、教学建议
模块2 ──→ agentic: （无直接调用，但日志数据是其他模块调用 agentic 的输入）
```

```
              └───────────┬───────────────┘
```

**数据流向原则**：

1. **模块1 → 所有模块**：知识点ID是全局引用，模块1是唯一的知识点数据源
2. **模块2 → 模块3/4/5**：模块2是学习行为数据的**主要采集者**，但不生产测评数据
3. **模块3 → 模块4/5**：模块3是测评数据的**唯一源**，成绩和错题由模块3产出
4. **模块4 和 模块5 互相配合**：模块4 专注于单个学生的理解和适配；模块5 专注于班级维度的分析和决策
5. **所有模块 → agentic**：遇到 LLM 推理需求时，各模块自行调用 agentic，不通过其他模块中转

### 12.4.1 前后端运行与接口调用约定

开发期统一采用“前端 3000 + 后端 8081 + Vue CLI 代理”的方式联调，避免浏览器跨域和端口不一致问题。

| 项目 | 地址 / 配置 | 说明 |
|------|-------------|------|
| 前端开发服务 | `http://localhost:3000` | Vue CLI dev server，浏览器访问入口 |
| 后端 API 服务 | `http://localhost:8081/practical-training` | Spring Boot 固定监听 `8081` |
| 后端 context-path | `/practical-training` | 见 `backend/src/main/resources/application.yml` 的 `server.servlet.context-path` |
| 前端代理规则 | `/practical-training` -> `http://localhost:8081` | 见 `frontend/vue.config.js` |
| 前端 Axios baseURL | `/practical-training` | 见 `frontend/src/api/index.js` |

前端代码中只写相对 API 路径，不直接写后端端口。例如：

```js
// frontend/src/api/index.js
api.get('/api/courses/search', { params: { keyword } })
```

浏览器实际请求：

```text
http://localhost:3000/practical-training/api/courses/search?keyword=...
```

Vue CLI dev server 代理到后端：

```text
http://localhost:8081/practical-training/api/courses/search?keyword=...
```

后端 Controller 中只声明 context-path 之后的路径，例如：

```java
@RestController
@RequestMapping("/api/courses")
public class CourseController {
    @GetMapping("/search")
    public Result<List<Course>> search(@RequestParam String keyword) {
        ...
    }
}
```

因此完整接口契约的书写格式应为：

```text
GET /practical-training/api/courses/search?keyword=...
```

本地启动建议：

```bash
# 后端：读取 backend/.env，并默认监听 8081
cd backend
set -a; source .env; set +a; mvn spring-boot:run

# 前端：监听 3000，并代理 /practical-training 到 8081
cd frontend
npm run serve -- --port 3000
```

也可以使用根目录启动脚本：

```bash
./start-dev.sh
```

`start-dev.sh` 默认使用后端 `8081`、前端 `3000`，并在启动后端前读取 `backend/.env`。

## 十四、游戏事件系统（爬塔游戏化引擎）

> 本节是[爬塔游戏化学习模式设计](毛瑞琪/爬塔游戏化学习模式设计.md)的**后端接口落地版本**。

### 14.1 架构原则

```
各业务模块                       模块4（游戏引擎）              受影响方
─────────                       ────────────────              ────────
模块2 学生提交任务 ──事件──→   ┌─────────────────┐
模块3 判分完成   ──事件──→   │  游戏状态机      │
模块1 楼层通关   ──事件──→   │  HP/ATK/DEF/EXP  │ ──状态变更──→ 模块1（楼层解锁）
模块3 Boss通关   ──事件──→   │  金币/精力/连胜   │ ──风险事件──→ 模块5（风险预警）
模块2 资源使用   ──事件──→   │  遗物判定/补给     │
                             └─────────────────┘
```

- **模块4 是唯一的游戏引擎**。所有游戏规则、属性计算、状态判定集中在模块4。
- **其余模块只发事件，不关心游戏逻辑**。每条事件一行代码。
- **Phase 1-2 不发事件，系统退化为纯CRUD模式**。Phase 3 开启游戏模式。

### 14.2 游戏状态模型（模块4 维护）

| 属性 | 初始值 | 计算规则 |
|------|--------|---------|
| HP（信心值） | 100 | 错题-10，连对+5（上限100），归零触发强制补给 |
| ATK（解题力） | 60% | 最近10题加权正确率（越近权重越高） |
| DEF（基础扎实度） | 从模块1取前置节点掌握度均值 | 随前置节点成绩动态更新 |
| EXP（经验值） | 0 | 每题+10，精英+40，Boss+100~400 |
| 等级 | Lv.1 入门 | EXP阈值：100/300/600/1000 → 入门/初级/中级/熟练/精通 |
| 金币 | 0 | 正确+20，Boss+100~800，商店兑换消耗 |
| 精力 | 5次/天 | 等级每升一级+1，每日0点重置 |
| 连胜计数 | 0 | 连对+1，错题归零 |

**所有属性按 `student_id + course_id` 为键，每个学生每门课独立一套游戏状态。**

### 14.3 游戏事件类型枚举

事件统一发到模块4的接口：

```
POST /practical-training/api/students/{studentId}/game-event
```

#### 14.3.1 答题类事件（模块3 发出）

| 事件类型 | 触发时机 | 携带字段 | 模块4 的处理 |
|---------|---------|---------|-------------|
| `answer_correct` | 学生答对一道题 | `question_id, knowledge_point_id, difficulty(1-5), is_first_attempt, time_spent_ms` | HP连对+5, EXP+10, 金币+20, 连胜+1, ATK更新, 检查连胜奖励 |
| `answer_wrong` | 学生答错一道题 | `question_id, knowledge_point_id, difficulty(1-5), attempt_count, error_type` | HP-10, 连胜归零, EXP+5（仍有经验）, 检查HP是否<30触发补给 |
| `answer_skipped` | 学生跳过一道题 | `question_id, knowledge_point_id` | 标记该知识点为"薄弱"，HP不变 |

#### 14.3.2 楼层类事件（模块1 / 模块3 发出）

| 事件类型 | 触发时机 | 携带字段 | 模块4 的处理 |
|---------|---------|---------|-------------|
| `floor_cleared` | 某层所有题完成（所有题正确率≥通关线） | `knowledge_point_id, correct_rate, is_perfect(全部一次对), time_total_ms` | EXP+楼层奖励, 金币+楼层奖励, 解锁下一层（通知模块1）, 检查遗物条件（完美主义等） |
| `boss_defeated` | Boss层通关 | `exam_id, knowledge_point_id, score, time_spent_ms, is_within_time_limit` | EXP+150~400, 金币+300~800, 检查遗物（速通者等）, 掉落高级补给, 精力+1 |
| `elite_defeated` | 精英怪层通关 | `knowledge_point_id, score` | EXP+80, 金币+160, 中等补给掉落 |
| `floor_failed` | 某层尝试后未通过 | `knowledge_point_id, correct_rate` | HP-20（Boss层额外惩罚）, 标记薄弱 |

#### 14.3.3 补给类事件（模块2 / 前端直接调用 发出）

| 事件类型 | 触发时机 | 携带字段 | 模块4 的处理 |
|---------|---------|---------|-------------|
| `supply_used` | 学生使用了补给 | `supply_type, target_kp_id, cost(金币消耗)` | 金币扣减, 应用补给效果（HP恢复/ATK临时加成/DEF提升）, 记录补给使用日志 |
| `hint_used` | 学生使用了提示 | `question_id, cost` | 金币-10, 记录"提示使用次数" |
| `ai_tutor_called` | 学生召唤AI导师 | `knowledge_point_id, trigger_reason` | 记录AI对话触发（万能灵药逻辑）, 不扣金币 |

#### 14.3.4 系统类事件（模块4 内部自动 / 定时触发）

| 事件类型 | 触发时机 | 模块4 的处理 |
|---------|---------|-------------|
| `hp_critical` | HP < 30 | 自动弹出补给选项（生命药水），通知模块5记录风险事件 |
| `stuck_detected` | 同一知识点连续失败≥3次 或 卡顿超10分钟 | 触发智能补给（万能灵药/先知之眼），通知模块5预警 |
| `daily_reset` | 每日0点 | 精力重置为 5 + 等级加成, 每日登录奖励 |
| `streak_3` | 连胜达到3 | ATK临时+10% |
| `streak_5` | 连胜达到5 | 金币收入×1.5, HP+5 |
| `streak_8` | 连胜达到8 | 获得临时遗物「势不可挡」：下一题ATK×2 |
| `streak_10` | 连胜达到10 | 解锁隐藏统计 |
| `level_up` | EXP达到升级阈值 | 等级+1, 精力上限+1, 通知前端展示升级动画 |

### 14.4 遗物触发条件表（模块4 判定）

| 遗物 | 触发条件 | 需监听的事件 | 数据来源 |
|------|---------|------------|---------|
| Pythonic | 使用列表推导式解题3次 | `answer_correct`（需前端传代码特征） | 模块3 |
| Debug之眼 | 自行发现并修复bug 5次 | `answer_correct` + `is_first_attempt=false` + `prev_error_type` | 模块3 |
| 数据魔术师 | Pandas题连续满分5题 | `answer_correct`（按知识点过滤+连续计数） | 模块3 |
| 一行超人 | 单行代码解题 | `answer_correct`（前端传代码行数=1） | 模块3 |
| 举一反三 | 未学关联知识点答对 | `answer_correct`（kp_id不在已学列表） | 模块1+模块3 |
| 速通者 | Boss层时限内完成 | `boss_defeated` + `is_within_time_limit=true` | 模块3 |
| 不死鸟 | HP归零后复出并通关 | `hp_critical` → 之后 `floor_cleared` 序列 | 模块4内部 |
| 夜枭 | 晚间(20:00-06:00)完成5题 | `answer_correct`（检查时间戳） | 模块3 |
| 完美主义 | 单层满分通关（全对无跳过） | `floor_cleared` + `is_perfect=true` | 模块1/模块3 |
| 助人者 | 讨论区帮助同学3次 | 讨论区事件（后续扩展） | 待定 |

### 14.5 各模块需要加的事件发送代码

#### 模块1（课程知识）需要加的

```
在"某知识点下所有题目被完成且通过"后：
  → 发 game_event("floor_cleared", {knowledge_point_id, correct_rate, is_perfect, time_total_ms})
  → 模块4 会回调模块1的"解锁下一层"接口（或直接查模块4获取楼层状态）
```

**模块1 新增对外接口**（供模块4调用）：
```
PUT /api/knowledge-points/{id}/floor-status
     body: { student_id, status: "locked"|"available"|"cleared"|"weak" }
     # 模块4 在楼层通关/失败后调用此接口更新节点状态
```

#### 模块2（任务跟踪）需要加的

```
在"学生提交任务"后：
  → 发 game_event("task_submitted", {task_id, task_type, knowledge_point_id})
  # 暂不影响游戏属性，但用于行为日志完整性

在"学生使用补给/提示"后（从资源/商店获取）：
  → 发 game_event("supply_used", {supply_type, target_kp_id, cost})
  → 发 game_event("hint_used", {question_id, cost})
```

#### 模块3（测评）需要加的 —— 最密集

```
在"判分完成"后：
  → answer_correct → game_event("answer_correct", {question_id, kp_id, difficulty, is_first_attempt, time_spent_ms})
  → answer_wrong   → game_event("answer_wrong", {question_id, kp_id, difficulty, attempt_count, error_type})

在"Boss考试批改完成"后：
  → boss_defeated  → game_event("boss_defeated", {exam_id, kp_id, score, time_spent_ms, is_within_time_limit})

在"精英题批改完成"后：
  → elite_defeated → game_event("elite_defeated", {kp_id, score})

在"AI批改报告/简答"后：
  → 若有评分 → 同 answer_correct / answer_wrong（按阈值判定）
```

#### 模块5（学情分析）需要加的 —— 接收方

```
模块5 不主动发游戏事件，但监听模块4的回调：

模块4 → 模块5：
  hp_critical    → 模块5记录风险事件 RiskAlert(risk_type="hp_critical")
  stuck_detected → 模块5记录风险事件 RiskAlert(risk_type="stuck")
  连续3天未登录   → 模块5记录风险事件 RiskAlert(risk_type="inactive")

模块5 对外新增接口（供模块4调用）：
POST /api/risk-alerts
     body: { student_id, course_id, risk_type, detail_json }
```

### 14.6 楼层状态管理（模块1 + 模块4 协作）

自适应塔地图的四色标记由模块1和模块4协作维护：

| 颜色 | 含义 | 判定规则 | 谁判定 | 谁存储 |
|------|------|---------|--------|--------|
| 🔒 暗色 | 锁定（前置未通过） | 前置知识点的楼层状态 ≠ `cleared` | 模块1（查前置依赖链） | 模块1 |
| 🔓 亮色 | 可挑战（推荐） | 前置全部已通 + 当前层未通 | 模块1 | 模块1 |
| ✅ 灰色 | 已掌握（跳过） | 正确率 ≥ 85%（数据来自模块3, 经模块4计算） | 模块4 计算掌握度 | 模块4 |
| 🔥 橙色 | 薄弱（建议补） | 正确率 40%~85% | 模块4 计算掌握度 | 模块4 |

前端查询入口统一为模块4：
```
GET /api/students/{id}/tower-map?course_id={id}
  → 返回每层的 {kp_id, floor_status, mastery_rate, is_accessible}
  → 模块4 内部调用模块1（前置依赖）和模块3（成绩）的数据来计算
```

### 14.7 游戏模式开关

```
GET /api/courses/{id}/config
  → 返回 { game_mode_enabled: true/false }

模块4 在各事件处理入口检查此开关：
  if (!gameModeEnabled) return; // 退化为纯CRUD，不更新游戏属性
```

Phase 1-2 期间 `game_mode_enabled = false`，所有人正常开发。Phase 3 打开开关，游戏引擎激活。
