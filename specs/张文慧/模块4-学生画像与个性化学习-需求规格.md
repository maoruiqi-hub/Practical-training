# 模块4：学生画像与个性化学习 — 需求规格

> 一句话定位：定义学生画像与个性化学习模块的功能需求——系统如何理解学生并给予适配支持，覆盖画像生成、能力评分、个性化推荐和成长激励。
> 阅读前置：[../项目需求.md](../项目需求.md)、[../../docs/architecture/模块接口与协作规范.md](../../docs/architecture/模块接口与协作规范.md)、[../common/authoring-conventions.md](../common/authoring-conventions.md)
> 状态：草拟

---

## 背景

当前系统已具备学生基础信息管理（CRUD + 登录注册）、任务提交记录和成绩统计。但系统对学生的理解仍停留在"单次成绩"层面，缺少：

- 对学生**整体学习状态**的持续追踪
- 对学生**薄弱点/优势点**的结构化描述
- 基于学习数据的**个性化推荐**能力
- 激励学生持续学习的**游戏化机制**

本模块以学生为核心，将任务、测评和学习日志数据转化为对学生学习状态的持续理解，支撑个性化学习支持。

---

## 目标

1. 建立学生画像体系，综合多源数据生成可量化的学习状态描述
2. 实现能力评分机制，按课程能力点持续追踪学生掌握度
3. 提供个性化推荐，帮助学生聚焦薄弱点、拓展优势点
4. 构建成长激励体系，用游戏化元素提升学习积极性

---

## 功能描述

### R1 组：学生信息管理

**R1.1** 系统应允许录入学生信息，包括学号、姓名、班级、联系方式、所属课程。

**R1.2** 系统应支持按学号、姓名、班级筛选查询学生列表。

**R1.3** 系统应支持批量导入学生信息（Excel/CSV 格式）。

**R1.4** 系统应支持批量导出学生信息为 Excel。

**R1.5** 如果导入数据格式不符合模板，则系统应逐行报错并继续导入有效行。

**R1.6** 当学号与已有学生重复时，系统应拒绝创建并提示"学号已存在"。

### R2 组：学习画像生成

**R2.1** 当学生查看个人画像时，系统应展示综合画像，包含 HP（信心值）、ATK（解题力）、DEF（基础扎实度）、EXP（经验值）、等级。

**R2.2** HP 计算规则：初始 100，每道错题 -10，连续正确 +5，上限 100，归零后强制弹出复习提示。

**R2.3** ATK 计算规则：最近 10 次答题的加权正确率，越近权重越高。

**R2.4** DEF 计算规则：前置知识点的平均掌握度。

**R2.5** EXP 计算规则：每题+10，测验任务+40，阶段综合测验+100~400。

**R2.6** 系统应基于学生答题数据自动更新画像，无需教师手动触发。

**R2.7** 画像数据应按课程维度独立计算，同一学生在不同课程拥有不同画像。

### R3 组：学习状态动态评估

**R3.1** 系统应根据近期任务完成、测验表现、登录频率评估学习状态。

**R3.2** 学习状态应分为四类：正常学习、进度滞后、能力提升、存在风险。

**R3.3** 当学生连续 7 天未完成任务时，系统应将状态标记为"进度滞后"。

**R3.4** 当学生连续 3 次测验正确率低于 40% 时，系统应将状态标记为"存在风险"。

**R3.5** 当学生最近 5 次答题正确率较前提升 15% 以上时，系统应将状态标记为"能力提升"。

**R3.6** 学习状态变更应在学生端首页可见，教师端风险学生应高亮提示。

### R4 组：能力评分动态更新

**R4.1** 系统应维护课程能力点体系，能力点从课程知识点映射生成（当前阶段：Mock 数据）。

**R4.2** 当学生完成任务、测验或提交报告后，系统应根据结果更新对应能力点的评分。

**R4.3** 能力评分取值范围 0~100，新学生初始值为 50。

**R4.4** 能力评分变更规则：答题正确+2（上限100），答题错误-1（下限0），测验任务得分按比例折算。

**R4.5** 学生端应展示个人能力雷达图（以课程能力点为维度）。

**R4.6** 能力评分应有变更历史，学生可查看近期变化趋势。

### R5 组：个性化学习推荐

**R5.1** 系统应根据学生画像和能力评分生成个性化推荐，推荐类型包括：知识点学习、复习材料、拓展材料、专项练习。

**R5.2** 当学生在某知识点错误率 ≥ 60% 时，系统应推荐该知识点的复习材料和基础练习。

**R5.3** 当学生在某能力点评分 ≥ 80 时，系统应推荐拓展材料和进阶任务。

**R5.4** 系统应为每条推荐生成推荐理由（基于规则模板，后续可接入agentic增强）。

**R5.5** 推荐列表应按优先级排序，紧急薄弱点优先于拓展推荐。

**R5.6** 学生可对推荐进行反馈（有用/跳过），系统应根据反馈调整后续推荐。

### R6 组：成长值与徽章管理

**R6.1** 系统应追踪学生成长值（积分/金币），正确答题 +20，阶段测验通过 +100~400。

**R6.2** 系统应实现等级体系：入门(0~199) → 初级(200~499) → 中级(500~999) → 熟练(1000~1999) → 精通(2000+)，按累计EXP判定。

**R6.3** 系统应实现 7 个学习徽章：

| 徽章 | 获取条件 |
|------|---------|
| Pythonic | 使用列表推导式 style 代码解题 ≥ 3 次 |
| Debug之眼 | 自行修正错误后正确 ≥ 5 次 |
| 速通者 | 测验限时内完成 |
| 完美主义 | 单次测验满分（无错题） |
| 连击王 | 连续 10 题正确 |
| 夜枭 | 非上课时段完成 ≥ 5 题 |
| 助人者 | 反馈中有价值的提问 ≥ 3 次 |

**R6.4** 徽章获得时，系统应向学生推送获得通知并在成长中心展示。

**R6.5** 系统应维护排行榜：按成长值/进度/徽章数排序，展示班级内排名。

**R6.6** 成长值变更应有明细记录（来源、数量、时间），学生可查历史。

### R7 组：学习反馈推送

**R7.1** 当学生完成一次测验后，系统应推送反馈摘要：得分、正确率、薄弱知识点、建议下一步行动。

**R7.2** 当学生画像属性（HP/ATK/DEF/等级）发生变化时，系统应在画像页展示变化动效。

**R7.3** 当学生获得新徽章或升级时，系统应推送通知并展示获得动画。

**R7.4** 系统应在学生端首页展示"今日学习建议"卡片，基于画像和推荐数据生成。

---

## 验收标准

1. 学生端 `/profile` 页面可正常访问，所有 Tab 有数据展示
2. 画像属性（HP/ATK/DEF/EXP/等级）能根据答题数据正确计算并更新
3. 能力雷达图展示至少 5 个课程能力点
4. 推荐列表 ≥ 3 条，各有明确推荐理由
5. 7 个徽章均可被正确触发和展示
6. 成长值变化有明细记录
7. 后端所有新增 API 返回统一 Result 格式
8. 前端与现有页面风格一致（Element Plus）

---

## 技术约束

- 后端：Spring Boot 3.5.15 + MyBatis-Plus 3.5.15，Java 17
- 数据库：MySQL 兼容（TiDB Cloud），自增 INT 主键
- 前端：Vue 3 + Element Plus + ECharts（雷达图）
- 鉴权：HttpSession，沿用现有 Auth 组件
- Mock 层接口必须对齐 `docs/architecture/模块接口与协作规范.md` 的模块间契约
- agentic 调用暂以 Mock 实现，接口签名与契约一致，可后续替换

---

## 不做（明确排除）

- 不实现真实 LLM 调用（agentic 暂为 Mock）
- 不新建模块1的知识点表和知识图谱可视化（属于模块1范围）
- 不新建模块2的学习日志采集端点（模块4通过Mock数据模拟日志查询）
- 不修改其他模块的表结构和现有 API
- 不实现跨课程的全局能力画像（仅按课程维度）
- 不实现教师端的学情分析和风险预警功能（属于模块5范围）
