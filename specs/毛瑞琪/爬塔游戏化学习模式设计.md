# 爬塔游戏化学习模式设计（合并终稿）

> **一句话定位**：将 Roguelike 爬塔游戏概念完整映射到「Python编程与数据分析基础」课程平台。整个平台就是一个游戏——塔地图 = 主界面，学习在爬塔中自然发生，资源按需在战斗中获取，而非常驻菜单。
> **阅读前置**：[项目需求.md](../项目需求.md)（需求背景）、[爬塔候选方案(codex).md](./爬塔候选方案(codex）.md)（Codex 战略提案）
> **状态**：✅ 已定稿，进入 docs/ 设计阶段

---

## 〇、定位与方案选择

### 定位：游戏感明显的学习闯关系统

不是"学习平台套了一层爬塔皮"，而是"学生进入的就是一个游戏"。功能不常驻菜单，而是在爬塔过程中按需触发：

```
传统学习平台：菜单 → 功能 → 使用 → 返回菜单
本系统：      进入塔 → 遇到挑战 → 补给自然弹出 → 继续爬 → Boss战 → 通关
```

### 方案选择：知识图谱爬塔（方案 2 / 3）

Codex 提出三种方案梯度，本项目选择**方案 2**：

| 方案 | 描述 | 选择？ |
|------|------|--------|
| 1. 轻量游戏化 | 课程页面套爬塔进度条 | ❌ 智能感弱，换皮而已 |
| **2. 知识图谱爬塔** | 图谱/题库/资源/推荐全接塔地图 | ✅ **本项目选择** |
| 3. 深度 Roguelike | 卡牌/遗物/随机事件/多角色 | ❌ 复杂度高，喧宾夺主 |

> **复杂度边界**：采用方案 2 为主体，有选择地吸收方案 3 中**低实现成本、高体验收益**的元素（遗物系统、补给系统、祝福选择），但不引入卡牌构筑、随机地图生成、多角色解锁等高复杂度机制。

## 一、爬塔原概念 → Python 课程 映射总表

### 1.1 塔与世界

| 爬塔原概念 | Python 课程对应 | 复杂度 |
|-----------|---------------|--------|
| **塔** | Python 编程与数据分析基础（唯一一门课） | 🟢 低 |
| **区域 (Act)** | 三大阶段：基础语法 → 数据处理 → 分析实战 | 🟢 低 |
| **楼层** | 一个知识点单元（如"列表与字典"） | 🟢 低 |
| **节点地图** | **知识图谱**（整个平台的主界面） | 🟡 中 |

### 1.2 房间类型（codex 贡献，核心组织概念）

每层楼内部由不同功能的**房间**组成，这是 Codex 方案最重要的贡献：

| 房间类型 | 课程含义 | 触发条件 | 复杂度 |
|---------|---------|---------|--------|
| 🔍 **诊断房** | 入层先做 1~3 道诊断题，判断掌握度 | 首次进入某层时自动触发 | 🟢 低 |
| ⚔️ **普通战斗房** | 单知识点练习题（选择/填空/基础编程） | 诊断未通过 → 进入战斗 | 🟢 低 |
| 💀 **精英战斗房** | 跨知识点综合题（读 CSV→清洗→统计） | 该区域前置层全部通关后可选 | 🟡 中 |
| 👑 **Boss 房** | 阶段综合大作业 / 数据分析报告 | 区域终点，前置层全清后解锁 | 🟡 中 |
| 📦 **补给房** | PPT/PDF/视频/代码示例/提示卡 | 战斗失败后弹出 / 学生主动进入 | 🟢 低 |
| 🔥 **营火房** | 阶段复盘、错题回顾、知识点巩固 | 每区域通关后开放 | 🟢 低 |
| 🎁 **宝箱房** | 拓展资料、优秀案例、代码模板 | Boss 击败后 / 隐藏条件触发 | 🟢 低 |

### 1.3 角色与属性

| 爬塔原概念 | Python 课程对应 | 计算逻辑 | 复杂度 |
|-----------|---------------|---------|--------|
| 英雄 | **学生画像** | 每个学生独立的属性面板 | 🟢 低 |
| HP（信心值） | 连续失败容忍度 | 初始 100，错题 -10，连对 +5，归零强制弹出补给 | 🟢 低 |
| ATK（解题力） | 当前知识点正确率 | 最近 10 题加权正确率（越近权重越高） | 🟢 低 |
| DEF（基础度） | 前置知识掌握度 | 前置节点掌握度均值，越高新题难度感知越低 | 🟢 低 |
| 精力 | 每日可挑战次数 | 初始 5 次/天，等级提升 +1/级 | 🟢 低 |
| 金币 | 积分货币 | 正确 +20，精英 +40，Boss +100~400 | 🟢 低 |
| EXP | 累计做题数 | 每题 +10，精英 +40，Boss +100~400 | 🟢 低 |
| 等级 | 能力评级 | 入门 → 初级 → 中级 → 熟练 → 精通 | 🟢 低 |

> 🟢 全部为确定性规则计算，不依赖 LLM。

### 1.7 遗物 / 成就（从方案 3 选择性吸收）

| 爬塔原概念 | Python 课程对应 | 复杂度 |

> ⚠️ **不引入**：卡牌 / 牌组构筑、随机地图生成、多角色解锁、诅咒卡牌——这些是方案 3 的内容。

### 1.8 元系统

| 爬塔原概念 | Python 课程对应 | 复杂度 |
|-----------|---------------|--------|

## 三、房间类型详解

### 3.1 🔍 诊断房（每层入口）

进入任何楼层，首先触发诊断房。系统出 1~3 道快速诊断题。

```
┌─────────────────────────────────────────┐
│  🔍 诊断房 · 第 6 层「数据结构」           │
│                                         │
│  快速检测你对列表、字典、集合的掌握程度...   │
│                                         │
│  Q1: 已知 scores = [85, 92, 78, 95]，   │
│      写出筛选 ≥ 90 分的列表推导式          │
│                                         │
│  [你的答案]                              │
│                                         │
│  ⏱ 预计 2 分钟  │  🔒 不消耗精力        │
└─────────────────────────────────────────┘
```

**判定规则（确定性，不用 LLM）**：

| 诊断结果 | 条件 | 行为 |
|---------|------|------|
| ✅ 已掌握 | 全部正确且用时 < 预期 | **跳过该层**，楼层变灰，直接解锁后续 |
| ⚡ 基本掌握 | 正确率 ≥ 50% | 给一道确认题，通过则跳过 |
| 🔥 薄弱 | 正确率 < 50% | 进入战斗房，开始学习 |
| 🔴 前置缺失 | 诊断题完全无法作答 | 提示回到前置层补基础 |

```
└─────────────────────────────────────────────┘
```

### 3.4 👑 Boss 房（区域终点）

覆盖该区域所有知识点的综合任务：

| Boss 层 | 位置 | 任务内容 | 评分方式 |
|---------|------|---------|---------|
| 🐍 基础 Boss | 4F | 3 道编程题覆盖 1-3F | 规则+LLM |
| 🐼 Pandas Boss | 9F | DataFrame 增删改查 + 综合 | 规则+LLM |
| 👑 最终 Boss | 14F | 原始数据→清洗→分析→可视化→报告 | LLM 初评+教师复核 |

### 3.5 📦 补给房（按需弹出）

**核心设计理念：补给不常驻菜单，在需要时自动弹出。**

| 补给名称 | 对应资源 | 触发时机 | 效果 |
|---------|---------|---------|------|
| 🧪 生命药水 | 复习讲义 PDF | HP < 30 自动弹出 | HP +40 |
| ⚗️ 力量灵药 | 代码示例 / 模板 | 同题失败 2 次后 | ATK 临时 +30% |
| 🛡️ 守护卷轴 | 官方文档链接 | 学生主动求助 | DEF 永久 +5% |
| 📜 智慧卷轴 | 教学视频片段 | 首次接触知识点 | 该层 ATK 永久 +10% |
| ✨ 万能灵药 | **AI 助教对话**（LLM 实时答疑） | 连续 3 次失败 | 对话式讲解 |
| 🔮 先知之眼 | 题目思路点拨 | 卡顿超 10 分钟 | 给方向不给答案 |
| 📦 知识宝箱 | 拓展阅读材料 | Boss 通关后 | 行业实战案例 |

### 3.6 🔥 营火房（阶段复盘）

每个区域通关后（4F/9F/14F），营火房自动开放：

- 查看该区域所有错题（弃牌堆回顾）
- 错题再战（从错题本重抽，达标后移除）
- 知识深挖（选择已通过的知识点，提升掌握度等级）
- 查看区域能力成长（ATK/DEF 变化曲线）

### 3.7 🎁 宝箱房（隐藏奖励）

| 触发条件 | 宝箱内容 |
|---------|---------|
| Boss 层满分通关 | 稀有遗物 + 拓展案例集 |
| 连续 5 题无错 | 金币 ×2 补给包 |

## 八、智能核心：规则引擎为主，LLM 按需辅助

### 8.1 分层原则

```
┌────────────────────────────────────────────────────┐
│                                                    │
│  🧠 LLM 智能（6 个按需调用点）                       │
│  知识图谱生成 · 入学诊断 · 编程题批改                 │
│  AI导师答疑 · 错因聚类 · Boss报告批改                 │
│                                                    │
│  ⚙️ 规则引擎（12 项确定性逻辑）                       │
│  楼层解锁 · 掌握度判定 · HP变化 · 补给触发             │
│  遗物条件 · 等级计算 · 金币结算 · 连击机制             │
│  排行榜 · 敌人发生器 · 错题本轮转 · 每日一题           │
│                                                    │
│  📐 知识图谱本体（静态结构）                          │
│  节点层级 · 前置依赖 · 难度标签 · 题型关联             │
│                                                    │
└────────────────────────────────────────────────────┘
```

**核心原则：能落规则的落规则，规则搞不定的才上 LLM。**

### 8.2 规则引擎负责的智能（不用 LLM）

| 智能行为 | 实现方式 |
|---------|---------|
| 楼层解锁 | 前置节点正确率 ≥85% → DAG 拓扑判定 |
| 掌握度四色标记 | 加权正确率 → 阈值映射（≥85%灰 / 40-85%橙 / 前置全过亮 / 否则暗） |
| 自适应补给投放 | HP<30 → 生命药水；失败 2 次 → 灵药；失败 3 次 → AI 答疑 |
| 自适应难度 | ATK 高 → 难度 +1 题；ATK 低 → 难度 -1 题 |
| 错题本轮转 | 错题标记 → 阶段结束重抽 → 连续正确 2 次移除 |
| 遗物触发 | 全部是计数/布尔条件，确定性 |

### 8.3 LLM 调用点（6 个，全部按需触发）

| 调用点 | 触发者 | 频率 | fallback |
|--------|-------|------|---------|
| ① 知识图谱生成 | 教师上传大纲后点按钮 | 每门课 1 次 | 教师手动编辑 |
| ② 入学诊断题生成 | 学生首次进入 | 每人 1 次 | 默认题库抽题 |
| ③ 编程题/简答题批改 | 提交后自动 | 每题 1 次 | 仅跑测试用例 |
| ④ AI 导师答疑 | 学生主动召唤 | 按需 | 弹出文档链接 |
| ⑤ 错因语义聚类 | 教师点按钮 | 按需 | 人工查看 |
| ⑥ Boss 报告批改 | 提交后自动 | 每 Boss 1 次 | 教师复核 |

### 8.4 自适应路线（知识图谱的天然智能）

不需要 LLM 规划路线。知识图谱 DAG + 掌握度规则 = 天然自适应：

```
学生 A（有基础）                   学生 B（零基础）
     │                                │
     ▼                                ▼
 入学诊断                          入学诊断
 1F✅ 2F✅ 3F🔥                    1F🔥 2F🔒 3F🔒
     │                                │
     ▼                                ▼
 塔地图渲染：                       塔地图渲染：
 1F 灰(跳过) 2F 灰(跳过)            1F 亮(推荐)

     │                                │
     ▼                                ▼
 选4F 直接挑战 Boss                  从1F 开始逐层爬
```

## 十二、可行性分析

### 12.1 复杂度分层

| 层 | 内容 | 复杂度 | 依赖 |
|----|------|--------|------|
| L1 规则引擎 | HP/ATK/金币/解锁/连击/排行榜 | 🟢 低 | 无 |
| L2 知识图谱 | 节点+边+四色+前置判定 | 🟡 中 | 后端 DAG + 前端 vis.js/D3 |
| L3 题库改造 | 敌人发生器+诊断房抽题+错题本 | 🟡 中 | 现有题库加字段 |
| L4 补给系统 | 触发+推送+商店+背包 | 🟡 中 | 规则触发+资源关联表 |
| L5 遗物/祝福 | 计数条件+查表效果 | 🟢 低 | 与 L1 同类 |
| L6 LLM 集成 | 6 个按需调用点 | 🟠 中高 | API + prompt + fallback |
| L7 游戏化 UI | 塔地图/战斗动画/特效 | 🟠 中高 | 前端动画库 |

### 12.2 与现有技术栈衔接

| 现有基础 | 爬塔化改造 |
|---------|-----------|
| 题库（Question 表） | + `room_type` / `floor_level` / `prerequisite` 字段 |
| 学习任务（LearningTask） | → 房间配置（类型+楼层+前置） |
| 任务提交（TaskSubmission） | + `hp_cost` / `supply_used` / `combo` 字段 |
| 成绩统计（ECharts） | → 爬塔战绩面板（进度/雷达图） |
| 课程（Course） | + 塔配置关联表 |

### 12.3 风险与缓解

| 风险 | 等级 | 缓解 |
|------|------|------|
| LLM API 不稳定 | 🔴 高 | 所有 LLM 调用有 fallback；批改用规则兜底 |
| 前端动画开发量大 | 🟡 中 | MVP 先做静态，动画后期迭代 |
| 知识图谱自动生成质量差 | 🟡 中 | 教师可手动编辑，LLM 只做初稿 |
| 游戏化影响学习严肃性 | 🟢 低 | 底层保留标准成绩字段，教师可导出传统成绩单 |

## 十三、MVP 分阶段计划

### Phase 1：规则引擎 + 静态塔地图（可玩骨架）— 不依赖 LLM

| 任务 | 工时 |
|------|------|
| 数据库扩展（题库加字段、战斗日志表、遗物表、补给表） | 2天 |
| 规则引擎（HP/ATK/掌握度/解锁/金币/连击） | 3天 |
| 静态塔地图（14层节点+四色渲染+点击进入） | 3天 |
| 诊断房+普通战斗房（抽题→答题→判定→结果） | 3天 |
| 英雄属性面板（实时刷新） | 1天 |

> **验收**：学生能看塔地图、进入楼层、答题、HP变化、楼层解锁。**零 LLM 依赖。**

### Phase 2：房间体系 + 补给 + 遗物（游戏感成型）

| 任务 | 工时 |
|------|------|
| 精英战斗房 + Boss 房 | 3天 |
| 补给系统（触发+推送+商店+背包） | 3天 |
| 营火房 + 宝箱房 | 2天 |
| 遗物 + 祝福系统 | 2天 |
| 游戏化 UI（战斗动画/连击特效/HP波动） | 3天 |

> **验收**：完整房间体系运转，补给按需弹出，遗物可收集生效。

### Phase 3：LLM 集成（智能化）

| 任务 | 工时 |
|------|------|
| 知识图谱自动生成 | 3天 |
| 入学诊断评测 | 2天 |
| 编程题 LLM 批改 | 2天 |
| AI 导师对话（流式） | 3天 |
| 战场复盘（问题聚类） | 2天 |

> **验收**：6 个 LLM 调用点可用，每个有 fallback。

### Phase 4：教师端 + 打磨

| 任务 | 工时 |
|------|------|
| 塔编辑器 | 3天 |
| 塔灵预警 | 2天 |
| 排行榜 + 成就墙 | 2天 |
| 联调 + 测试 | 3天 |

## 十四、验收清单

- [ ] 学生登录后主界面是塔地图，不是传统菜单
- [ ] 知识图谱可视化：节点=知识点，边=前置依赖，四色标记状态
- [ ] 已掌握知识点自动变灰跳过，**不强制重复学习**
- [ ] 每层入口先过诊断房，根据结果决定跳过/战斗/回退
- [ ] 做错题后弹出对应补给，补给与错因关联到具体知识点
- [ ] HP 归零强制弹出补给，学生可再战
- [ ] Boss 层 = 综合任务，覆盖区域所有知识点
- [ ] 属性面板（HP/ATK/DEF/EXP）实时更新
- [ ] 遗物可收集，效果可感知
- [ ] 教师能编辑塔结构、配置房间、查看通关进度和薄弱点
- [ ] 教师端显示塔灵预警
- [ ] AI 导师任何界面可召唤，基于当前知识上下文回答
- [ ] 所有 LLM 调用点有 fallback，LLM 不可用时系统不崩溃
- [ ] 教师可导出传统成绩单，游戏化评分不替代课程评价

## 十五、失败条件

以下任一发生 = 项目失败：

1. ❌ 只是把按钮和页面改名成"爬塔"，学习路径仍然固定线性
2. ❌ 已经会的内容不能跳过，所有学生走同样路线
3. ❌ 补给和错因没有关联到具体知识点，随机弹资料
4. ❌ 教师无法审核和编辑系统生成的知识图谱
5. ❌ 学生成绩只剩游戏分数，失去传统课程评价意义
6. ❌ LLM 调用成为系统瓶颈，API 不可用系统就瘫痪
7. ❌ 游戏化 UI 喧宾夺主，学生关注刷分而不是真正学 Python
