**每层战斗形式**
每个知识点房间可以按“诊断 → 挑战 → 反馈 → 补给 → 再挑战”组织。

学生进入某层后，系统先给 1-3 道诊断题；如果掌握度高，就直接跳过。若掌握度不够，则进入战斗：选择题/填空题适合普通怪，简答题/编程题适合精英怪，报告/PDF/Word 提交适合 Boss。学生做错或做不出来时，不是简单判错，而是弹出补给：先给提示，再给对应知识点资料，再给前置知识点的补救练习。补给使用后可以重战，系统记录“是否靠提示完成”，这会影响掌握度判断。

**功能融入**
基础功能可以这样嵌入：

学生信息管理 = 玩家档案，记录班级、课程、学习画像、掌握度。  
课程基本信息管理 = 塔的基本配置，包括课程名、教师、学分、总楼层。  
学习任务管理 = 教师配置房间、怪物、Boss、截止时间和提交方式。  
学习数据采集 = 战斗日志，记录得分、耗时、错误、提示使用、重试次数。  
成绩分析展示 = 通关进度、楼层成绩、能力雷达图、趋势曲线。

拓展功能可以这样嵌入：

多任务类型 = 多种房间类型，比如视频房、阅读房、答题房、报告 Boss 房。  
知识图谱可视化 = 塔地图，节点可悬停查看简介，点击进入知识点详情。  
资源上传下载 = 补给库，教师上传 PPT/PDF/视频，学生按需领取。  
视频进度记录 = 补给使用日志，重复观看片段可推断该知识点薄弱。  
题库与组卷 = 怪物库，按知识点、难度、题型生成不同战斗。

创新功能可以这样嵌入：

LLM 提取知识点 = 一键生成塔地图。  
个性化推荐 = AI 路线规划器，推荐下一层、补给、复习材料。  
能力图谱 = 角色属性面板，比如理解、分析、实践、表达、编程能力。  
智能批改 = Boss 裁判，对报告、论文、简答进行评分和反馈。  
自主创新 = “跳层机制 + 错因诅咒 + 自适应补给”会比较亮眼。

**智能核心**
关键不是“让所有人爬同一座塔”，而是“同一座塔，每个人看到的路线不同”。

系统给每个知识点维护一个状态：未测、薄弱、学习中、已掌握、遗忘风险。数据来自诊断题、任务得分、答题耗时、提示使用、视频观看行为、报告批改结果。若某知识点掌握度高且证据足够，就不要求学习，直接跳过；若掌握度高但证据不足，只给一道确认题；若前置知识薄弱，就先弹补给或回到前置层。

**三种方案**
1. 轻量游戏化：只把课程页面包装成爬塔进度，成本低，但智能感弱。
2. 知识图谱爬塔：把图谱、题库、资源、推荐全部接到塔地图上，我推荐这个，最贴合需求。
3. 深度 Roguelike：加入卡牌、遗物、随机事件，趣味强，但复杂度高，容易喧宾夺主。

**验收清单**
- 学生能看到自己的课程塔地图。
- 已掌握知识点可以跳过，而不是强制重复学习。
- 做错题后能获得对应补给，不只是显示答案。
- 教师能上传资源、配置任务、查看学生通关和薄弱点。
- AI 推荐能解释“为什么推荐这个知识点/资源”。

**失败条件**
- 只是把按钮和页面改名成“爬塔”，但学习路径仍然固定。
- 已经会的内容不能跳过。
- 补给和错因没有关联到具体知识点。
- 教师无法审核 AI 生成的知识图谱。
- 学生成绩只剩游戏分数，失去课程评价意义。

**课程塔**
`Python编程与数据分析基础` 就是一座塔，目标是从“能写基础 Python”一路爬到“能完成一个简单数据分析报告”。

**楼层概念对应**
| 爬塔概念 | 本课程对应 |
|---|---|
| 第 1 层 | Python 基础语法：变量、类型、输入输出 |
| 第 2 层 | 条件判断与循环 |
| 第 3 层 | 列表、字典、元组等数据结构 |
| 第 4 层 | 函数与模块 |
| 第 5 层 | 文件读写与异常处理 |
| 第 6 层 | NumPy 基础 |
| 第 7 层 | Pandas 数据读取、筛选、清洗 |
| 第 8 层 | 数据统计与分组分析 |
| 第 9 层 | Matplotlib / 可视化基础 |
| Boss 层 | 完成一个小型数据分析项目报告 |

**房间类型**
| 房间 | 课程含义 |
|---|---|
| 诊断房 | 入门小测，判断学生是否已经会这个知识点 |
| 普通战斗房 | 单知识点练习题，比如写一个循环、筛选 DataFrame |
| 精英战斗房 | 多知识点组合题，比如读 CSV 后清洗并统计 |
| 补给房 | PPT、PDF、教学视频、示例代码、提示卡 |
| 营火房 | 阶段复盘、错题总结、知识点回顾 |
| 宝箱房 | 拓展资料、优秀案例、可复用代码模板 |
| Boss 房 | 提交数据分析报告或 notebook，由系统/教师评分 |

**战斗概念对应**
普通怪可以是基础编程题，例如“用循环统计列表中的偶数”。  
精英怪可以是数据处理题，例如“读取学生成绩 CSV，计算每门课平均分”。  
Boss 可以是综合任务，例如“分析某份销售/成绩/电影数据集，完成清洗、统计、可视化和结论说明”。

**补给概念对应**
补给不是随机给资料，而是根据卡住的位置给：

- 语法补给：变量、循环、函数的短讲解
- 示例补给：一段可运行 Python 代码
- 数据补给：示例 CSV / Excel 数据集
- 工具补给：Pandas 常用 API 表、Matplotlib 图表模板
- 提示补给：只提示下一步，不直接给完整答案
- 回退补给：如果 Pandas 做不动，回到“列表/字典/文件读取”等前置层

**智能核心**
学生第一次进入这门课时先做“入塔诊断”。系统根据答题结果给每个知识点打状态：

- 已掌握：直接跳过，不强制学习
- 基本掌握：给一道确认题，通过后跳过
- 薄弱：进入对应楼层学习
- 前置缺失：先回到更低楼层补基础

比如一个学生已经会 Python 变量、循环、列表，但不会 Pandas，那么前 1-3 层可以直接点亮，从 Pandas 相关楼层开始爬。这样“已经会的不用学”就变成页面流程里的核心机制，而不是一句口号。

**基础/拓展/创新功能融入**
学生信息管理 = 玩家档案。  
课程信息管理 = 这座塔的基本信息。  
任务管理 = 教师配置每层房间和 Boss。  
学习数据收集 = 战斗记录、耗时、错误、提示使用情况。  
成绩展示 = 爬塔进度、知识点掌握图、能力雷达图。  
资源上传下载 = 补给库。  
视频学习记录 = 学生在哪些补给上停留或反复观看。  
题库组卷 = 自动生成普通怪、精英怪、Boss 前测。  
知识图谱 = 这座塔的地图。  
LLM 推荐 = 判断下一层该学什么、该跳过什么、该补什么。  
智能批改 = 批改代码题、简答题、数据分析报告。

这个版本不用做很多课程，只把一门课做透：一座塔、一张知识图谱、一套诊断跳层机制，就能突出创新点。
