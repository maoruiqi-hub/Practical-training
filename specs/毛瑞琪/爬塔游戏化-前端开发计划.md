## 〇、前置说明：两份预留事项

在开始开发之前，明确以下两项工作**不由本文档计划覆盖**，由团队其他同学负责：

### 预留 1：数据库接入

| 项目 | 说明 |
|------|------|
| **当前状态** | 开发期使用 H2 内存数据库（`jdbc:h2:mem:practical_training;MODE=MySQL`），表结构定义见 `schema.sql`，测试数据见 `data.sql` |
| **目标状态** | 切换至金仓 KingbaseES 关系型数据库 |
| **负责人** | 团队数据库负责同学 |
| **对本文档的影响** | 前端开发继续使用 H2 开发，API 路径和字段名不变。数据库切换后仅需修改 `application.yml` 数据源配置，不影响前端代码 |
| **阻塞风险** | ⚠️ 表结构中模块4新表（`student_profile`、`competency_score`、`achievement` 等）使用了 `VARCHAR(36)` UUID 主键，而旧表使用 `INT AUTO_INCREMENT`。数据库切换时需确认金仓支持此混合模式 |

### 预留 2：LLM / Agentic 服务

| 项目 | 说明 |
|------|------|
| **当前状态** | 后端 `AgenticClient` 已实现，但运行在 **mock 模式**（`agentic.mode=mock`）。mock 模式下所有 AI 调用返回固定假数据，不影响系统运行 |
| **目标状态** | 启动独立 agentic 服务（Python），提供知识图谱生成、智能批改、AI 对话、个性化推荐、风险检测、问题聚类、教学建议 7 个能力 |
| **负责人** | 团队 AI/agentic 负责同学 |
| **对本文档的影响** | 前端开发**不依赖 agentic**。爬塔核心（塔地图、诊断、战斗、属性面板、补给）全部由规则引擎驱动，零 LLM 依赖。agentic 就绪后，仅在以下场景增强体验：AI 导师答疑弹窗、编程题 LLM 风格点评、Boss 报告智能批改 |
| **降级策略** | agentic 不可用时，所有 LLM 功能入口显示"AI 服务暂不可用，请使用常规资源"，系统不崩溃（已通过 `AgenticResponse.unavailable()` 实现） |

#### 1.2.2 爬塔游戏引擎已实现能力

模块4（`profile/` 包）已内置了游戏引擎的大部分逻辑：

| 引擎能力 | 实现位置 | 说明 |
|---------|---------|------|
| **游戏事件总线** | `common/GameEventTypes.java`（13种事件类型常量）、`common/event/GameEvent.java`（统一消息体）、`common/event/SpringGameEventPublisher.java`（进程内发布） | 各模块通过 Spring 事件机制通信 |

### 2.2 设计简化决策

| 砍掉 | 理由 |
|------|------|
| 精英战斗房 (💀) | 跨知识点综合题 = Boss 房可覆盖 |

| 祝福系统 (开局 5 选 1) | 全局系数传导复杂 |
| 连击特效 (3/5/8/10 题) | 保留数据逻辑，砍掉前端动画 |

| 教师端塔编辑器 | Phase 2，当前先手动 SQL 配置塔结构 |

#### 任务 A2：塔地图数据源切换（0.5天）

**文件**：`profile/service/impl/ProfileServiceImpl.java`

**改动**：`getTowerMap()` 和 `getCourseAbilityMap()` 方法从 `AbilityPoint` 切换为 `KnowledgePoint` + `KnowledgeRelation`

**关键逻辑**：
```java
// 改造前：用 AbilityPoint 做楼层
List<AbilityPoint> abilityPoints = abilityPointService.listByCourseCode(...);

// 改造后：用 KnowledgePoint + KnowledgeRelation 做楼层
List<KnowledgePoint> kps = knowledgePointService.listByCourse(courseId);
List<KnowledgeRelation> relations = knowledgeRelationService.getByCourse(courseId);
// 用 relations 构建前置依赖 DAG → 判定每层锁定/可挑战状态
```

**验收**：`GET /api/students/{id}/tower-map?course_id=1` 返回 14 层，每层有正确的四色状态和前置依赖关系

#### 任务 A3：模块3 答题后发游戏事件（0.5天）

**文件**：`controller/TaskSubmissionController.java` 或对应的判分 Service

**改动**：在判分完成后加一行：
```java
// 判分完成后，发布游戏事件
if (gameConfigService.isEnabled(courseId)) {
    gameEventPublisher.publish(GameEvent.builder()
        .eventId(SharedIds.newId())
        .eventType(correct ? GameEventTypes.ANSWER_CORRECT : GameEventTypes.ANSWER_WRONG)
        .studentId(String.valueOf(studentNo))
        .courseId(courseId)
        .sourceId(questionId)
        .occurredAt(LocalDateTime.now())
        .payload(Map.of("question_id", questionId, "knowledge_point_id", kpId,
                        "difficulty", difficulty, "task_type", taskType))
        .build());
}
```

**注意**：如果判分逻辑分散在多处，统一收到一个公共服务方法中处理。

**验收**：学生答对一题 → `GET /api/students/{id}/profile?course_id=1` → HP/EXP/金币有变化

### 3.4 Phase C：前端楼层战斗流程（1.5天）

> **目标**：塔地图点击楼层 → 进入楼层页面 → 诊断 → 战斗（答题）→ 结算 → 返回塔地图

#### 任务 C1：FloorView.vue — 楼层页面框架（0.5天）

**路由**：`/floor/:kpId`

**组件结构**：
```vue
<template>
  <div class="floor-view">
    <GameHud :profile="profile" />
    <!-- 步骤1：诊断房 -->
    <DiagnosisRoom v-if="step === 'diagnosis'" :kpId="kpId"
      @diagnosed="onDiagnosed" />
    <!-- 步骤2：战斗房 -->
    <BattleRoom v-else-if="step === 'battle'" :kpId="kpId"
      @battle-end="onBattleEnd" />
    <!-- 步骤3：Boss房（仅Boss层触发） -->
    <BossRoom v-else-if="step === 'boss'" :kpId="kpId"
      @boss-end="onBossEnd" />
  </div>
</template>
```

**步骤机**：
```
进入楼层 → step='diagnosis'
       ↓
  诊断结果：
    mastered(≥85%) → 标记跳过，返回塔地图
    partial(40-84%) → step='battle'（出1-3道战斗题）
    none(<40%) → step='battle'（出3-5道战斗题）
    prerequisite_missing → 提示回前置层
       ↓
  step='battle'：答题...
       ↓
  房间通关判定：正确率≥通关线(70%)？
    是 → 本层标记 cleared，返回塔地图
    否 → HP<30？弹出补给 / 可再战
       ↓
  （若是Boss层）step='boss'：综合题...
       ↓
  Boss通关 → 区域通关，返回塔地图
```

**验收**：能按步骤走完整流程

---

#### 任务 C2：DiagnosisRoom.vue — 诊断房（0.25天）

**UI**：与战斗房类似但更轻量

**关键逻辑**：
```javascript
// 从后端抽 1-3 道该知识点的诊断题
const questions = await getQuestionsByKnowledgePoint(kpId, { count: 3, type: 'diagnosis' })
// 学生作答
// 判定：
if (correctRate >= 0.85) emit('diagnosed', 'mastered')
else if (correctRate >= 0.40) emit('diagnosed', 'partial')
else emit('diagnosed', 'weak')
```

**验收**：诊断完成后根据正确率走不同分支

---

#### 任务 C3：BattleRoom.vue — 战斗房（0.5天）

**核心逻辑**：复用现有 `QuizTake.vue` 的答题 UI（题目渲染、代码编辑器、提交判定），加上：

1. **敌人信息面板**（题目前置展示）：
```html
<div class="enemy-card">
  <h3>🐍 敌人：{{ question.knowledgePoint }}</h3>
  <p>考察：{{ question.topics }}</p>
  <p>难度：{{ '⭐'.repeat(question.difficulty) }}</p>
  <p>预计：{{ question.estimatedTime }} 分钟</p>
  <p>奖励：EXP+{{ reward.exp }} 金币+{{ reward.coins }}</p>
</div>
```

2. **战斗操作栏**：
```html
<div class="battle-actions">
  <el-button type="primary" @click="submitAnswer">⚔️ 提交</el-button>
  <el-button @click="useHint">💡 提示 (-10💰)</el-button>
  <el-button @click="openSupply">📦 补给</el-button>
  <el-button @click="skip">🏃 跳过</el-button>
</div>
```

3. **提交后处理**：
```javascript
async function submitAnswer() {
  // 1. 提交答案到后端
  const result = await submitAnswer(taskNo, answer)
  // 2. 发送游戏事件
  await sendGameEvent(studentId, {
    course_id: courseId,
    event_type: result.correct ? 'answer_correct' : 'answer_wrong',
    question_id: questionId,
    knowledge_point_id: kpId,
    difficulty: difficulty,
    task_type: 'quiz'
  })
  // 3. 刷新 profile
  const profile = await getProfile(studentId, courseId)
  // 4. 显示战斗结算动画
  showBattleResult(result.correct, profile)
}
```

**可复用组件**：`QuizTake.vue` 已有题目渲染、选项选择、代码编辑器、答案提交逻辑

**验收**：答题 → 发送游戏事件 → 属性面板变化 → 结算反馈

#### 任务 C4：BossRoom.vue — Boss 房（可选，0.25天）

**差异点**：Boss 层题目为综合题（1-2道），覆盖区域所有知识点

**可复用** `BattleRoom.vue` 的组件结构，区别是：

**验收**：Boss 层通关后返回塔地图，该区域楼层全部标记 cleared

### 3.5 Phase D：联调测试 + 验收（1.5天）

#### 任务 D1：全链路联调（0.5天）

走通完整流程：
1. 学生登录 → 进入塔地图 → 看到 14 层四色状态
2. 点击可挑战楼层 → 诊断房 → 战斗房 → 答题
3. 答对 → HP/EXP/金币 变化 → ATK 更新
4. 答错 → HP-10 → HP<30 弹补给 → 使用补给 → HP 回升
5. 楼层通关 → 塔地图该层变灰 → 下一层解锁
6. Boss 通关 → 区域通关 → 排行榜更新

#### 任务 D2：边缘情况测试（0.5天）

| 测试场景 | 预期行为 |
|---------|---------|
| 诊断全部正确 | 跳过该层，楼层变灰 |
| 连续答错 3 题 | HP 降为 70，无补给（HP>30） |
| HP 降到 28 | 自动弹出补给弹窗 |
| 使用所有精力次数 | 提示"今日挑战次数已用完" |
| 点击锁定楼层 | 提示"请先通关前置楼层" |
| 刷新页面 | 塔地图状态持久化（后端存储） |
| game_mode_enabled=false | 答题后 HP/EXP 不变 |

#### 任务 D3：验收清单（0.5天）

对照简化版验收标准：

- [ ] 学生登录后主界面是塔地图，不是传统菜单

- [ ] 已掌握知识点自动变灰跳过（诊断正确率≥85%）
- [ ] 楼层入口先过诊断房，根据结果决定跳过/战斗/回退
- [ ] 答题后属性面板（HP/ATK/DEF/EXP/金币）实时更新
- [ ] HP<30 时自动弹出补给选项
- [ ] Boss 层 = 综合任务，通关后区域解锁
- [ ] 教师端可查看学生爬塔进度（已有 TeacherStudentProfile.vue）
- [ ] LLM 不可用时系统不崩溃（AI 入口显示"暂不可用"）
- [ ] 教师可导出传统成绩单（已有模块5 报表导出）

## 五、失败条件（红线）

以下任一发生 = 本计划失败：

1. ❌ 塔地图只是换皮菜单，点击楼层后仍然是传统刷题流程
2. ❌ 诊断后没有真正跳过已掌握内容，所有学生走同样路线
3. ❌ 补给随机弹出，与错因/HP 状态无关
4. ❌ 答题后属性面板不更新（游戏事件链路未打通）
5. ❌ 页面刷新后塔地图状态丢失（没有持久化到后端）
6. ❌ agentic 不可用时前端白屏或报错
