# 模块5 需求文档：学情分析与教学决策

> **一句话定位**：定义模块5（学情分析与教学决策）的全部功能需求——它是教师视角的数据消费与决策支持层，从模块1~4汇聚数据，产出成绩分析、进度监控、风险预警、共性问题聚类与教学建议。
> **阅读前置**：[../项目需求.md](../项目需求.md)（需求背景）、[../模块接口与协作规范.md](../模块接口与协作规范.md)（模块间接口契约）、[./爬塔游戏化学习模式设计.md](./爬塔游戏化学习模式设计.md)（游戏事件集成）
> **状态**：草拟

---

## 一、背景

在 AI 智慧课程平台中，模块1~4 分别负责课程知识组织、学习任务跟踪、测评评价、学生画像。但这些数据分散在各模块中，教师缺乏一个统一的视角来理解班级整体状况：

- 哪些学生进度落后、存在学习风险？
- 班级在哪些知识点上普遍薄弱？
- 学生的成绩如何随时间变化？
- 系统能否主动提示教师关注异常学生？
- 学生共同的错题和疑问集中在哪些地方？

模块5 就是为回答这些问题而存在的。它是教师端的"驾驶舱"，消费模块1~4 的数据，结合 agentic 服务的 LLM 推理能力，产出可操作的分析结果与教学建议。

**核心设计原则**：
- 模块5 **只读消费**其他模块数据，不持有学生、课程、任务、试题的写入权
- 预警和建议**只提示、不自动执行**——最终决策权始终在教师手中
- 与爬塔游戏引擎协作：接收模块4的游戏风险事件（HP临界/卡顿/不活跃），转化为教师端预警

---

## 二、目标

| 目标 | 可检验标准 |
|------|-----------|
| 班级管理 | 教师能创建/修改班级，添加学生，查询班级列表 |
| 成绩分析 | 教师能查看班级成绩总览、学生个人成绩变化趋势（柱状图/曲线图数据），数据延迟 ≤ 2 秒 |
| 进度监控 | 教师能查看班级整体学习进度和单个任务完成率，数据每 5 分钟自动刷新 |
| 风险预警 | 系统自动识别拖延/低分/未登录/进度落后/HP临界/卡顿 6 类风险，教师端高亮展示 |
| 共性问题聚类 | 教师触发后，系统汇总错题和反馈，按主题聚类输出班级高频问题列表 |
| 教学建议 | 教师触发后，系统结合薄弱知识点和聚类结果，生成教学调整建议 |
| 报表导出 | 教师能导出 Excel/PDF 格式的成绩报表和分析报告 |
| 游戏事件集成 | 接收模块4的 hp_critical / stuck_detected / inactive 事件，自动生成风险记录 |

## 三、功能描述（EARS 需求）

### R1 组：班级管理

> 教师通过班级维度组织学生，班级是模块5 所有分析操作的基础聚合单元。

**R1.1** 系统应允许教师创建班级，录入班级名称、关联课程、学期信息。

**R1.2** 当教师修改班级信息时，系统应保存修改记录并更新最后修改时间。

**R1.3** 教师登录后，系统应展示该教师所管理的全部班级列表（按学期筛选）。

**R1.4** 当教师查看某个班级详情时，系统应返回班级基本信息及其包含的学生列表（学生姓名 + 学号 + 邮箱）。

**R1.5** 系统应允许教师向班级中添加学生（通过学生ID或批量导入学号列表）。

**R1.6** 系统应允许教师从班级中移除学生（不删除学生账号，仅解除班级归属）。

**R1.7** 如果班级中已有学生，则系统不应允许删除该班级；应先提示教师将学生移除或转移。

**R1.8** 如果同一课程下班级名称重复，则系统应拒绝创建并提示"该课程下班级名称已存在"。

### R2 组：成绩分析

> 模块5 从模块3 消费成绩数据，按班级/学生/时间维度聚合，为教师提供多角度成绩视图。

**R2.1** 当教师查看班级成绩总览时，系统应向模块3 查询该班级所有学生的各任务/考试得分，返回聚合数据：
- 班级平均分、最高分、最低分、标准差
- 各分数段人数分布（0-59 / 60-69 / 70-79 / 80-89 / 90-100）
- 每个学生的总分及排名

**R2.2** 当教师指定时间范围查看成绩趋势时，系统应向模块3 查询该时间段内的成绩记录，按周（或按考试节点）聚合，返回可绘制柱状图/曲线图的数据结构（含横轴标签 + 纵轴数值）。

**R2.3** 当教师查看某个学生的成绩变化时，系统应返回该学生在课程中所有已评分任务的得分序列（按时间排序），以及与班级平均分的对比。

**R2.4** 当教师按知识点维度查看成绩时，系统应向模块3 查询错题统计，结合模块1 的知识点信息，返回各知识点的得分率排名（从低到高，标出薄弱知识点）。

**R2.5** 系统应在 2 秒内返回成绩查询结果（不含导出）。

---

### R3 组：学习进度监控

> 模块5 从模块2 消费进度数据，以班级视角呈现整体和个体的学习推进情况。

**R3.1** 当教师查看班级整体学习进度时，系统应向模块2 查询该班级所有学生的进度数据，返回：
- 班级平均完成率（已完成任务数 / 总任务数）
- 各任务的平均完成率
- 进度落后学生列表（完成率低于班级平均 20% 以上）

**R3.2** 当教师查看某个任务的完成详情时，系统应向模块2 查询该任务的提交统计：
- 已提交人数 / 未提交人数
- 按时提交率 / 延迟提交率
- 未提交学生名单

**R3.3** 当教师查看某个学生的学习进度时，系统应向模块2 查询该生的任务完成清单（每个任务的状态：未开始 / 进行中 / 已提交 / 已批改），按截止时间排序。

**R3.4** 在学习进度页面，系统应每 5 分钟自动刷新数据（或教师手动刷新），保证教师看到的是近实时状态。

### R4 组：学习风险预警

> 模块5 是风险预警的汇聚中心：既自行从模块1~4 数据中检测风险，也接收模块4 游戏引擎推送的风险事件。

#### 4.1 风险检测规则（确定性，不依赖 LLM）

**R4.1** 系统应根据以下规则自动判定学习风险：

| 风险类型 | 判定规则 | 风险等级 |
|---------|---------|---------|
| `procrastination`（任务拖延） | 有任务距截止时间 < 24h 且尚未提交 | 中 |
| `procrastination`（严重拖延） | 有任务已超过截止时间且未提交 | 高 |
| `low_score`（连续低分） | 最近 3 次评分均低于 60 分 | 高 |
| `score_decline`（成绩下滑） | 最近 3 次评分趋势持续下降且最新 < 70 | 中 |
| `inactive`（长期未登录） | 连续 3 天无学习日志记录 | 中 |
| `inactive`（严重不活跃） | 连续 7 天无学习日志记录 | 高 |
| `progress_lag`（进度落后） | 完成率低于班级平均 30% 以上 | 中 |
| `hp_critical`（HP 临界） | 模块4 推送游戏 HP < 30 事件 | 高 |
| `stuck`（学习卡顿） | 模块4 推送同一知识点连续失败 ≥ 3 次 | 中 |

**R4.2** 当教师手动触发风险检测（或系统定时每日执行）时，系统应向模块2 查询学习日志和进度、向模块3 查询成绩数据、向模块4 查询画像数据，逐学生按 R4.1 规则判定，生成 `RiskAlert` 记录。

**R4.3** 如果同一学生同时命中多条风险规则，系统应合并为一条综合预警，风险等级取最高者，`detail` 字段包含所有命中类型及对应数据。

**R4.4** 系统不应重复生成相同风险类型的预警：如果某学生已有未解除的同类型预警，则跳过本次生成。

#### 4.2 预警展示

**R4.5** 当教师查看班级风险预警列表时，系统应返回该班级所有未解除的预警，按风险等级（高→中→低）和时间（新→旧）排序：
- 高风险学生高亮置顶（红色标记）
- 每条预警展示：学生姓名、风险类型中文描述、风险等级、触发时间、关键数据摘要

**R4.6** 当教师查看某个学生的风险详情时，系统应展示该生当前风险状态（所有未解除预警 + 历史预警记录 + HP/进度/成绩等关键指标快照）。

**R4.7** 当教师标记预警为"已处理"时，系统应更新该预警状态并记录处理时间，已处理预警不再出现在默认列表中（可通过"历史预警"查看）。

#### 4.3 游戏事件接收

**R4.8** 当模块4 向模块5 发送游戏风险事件（`hp_critical` / `stuck_detected` / `inactive`）时，模块5 应接收并自动按 R4.1 规则创建对应的 `RiskAlert` 记录。

**R4.9** 模块5 应暴露以下接口供模块4 写入风险事件：

```
POST /practical-training/api/risk-alerts
     body: { student_id, course_id, risk_type, detail_json }
     # risk_type 取值: "hp_critical" | "stuck_detected" | "inactive"
```

### R5 组：共性问题聚类

> 教师触发后，系统汇总全班错题、提问和反馈，通过 agentic 服务进行语义聚类，识别班级共性薄弱点。

**R5.1** 当教师触发共性问题分析时，系统应执行以下数据汇聚：
- 向模块3 查询班级错题统计数据（`getClassMistakeStats`）
- 向模块3 查询学生错题详情（含错误答案、正确答案、知识点关联）
- 向模块2 查询学生提交中的反馈和疑问文本（`Submission` 中的 `content` / `feedback` 字段）

**R5.2** 数据汇聚完成后，系统应将错题信息和反馈文本发送至 agentic 服务 `/api/agent/cluster-problems`，请求 LLM 进行语义聚类，返回聚类结果列表。

**R5.3** agentic 返回的聚类结果每项应包含：

| 字段 | 说明 |
|------|------|
| `topic` | 问题主题（如"列表推导式语法混淆"） |
| `count` | 涉及学生数 |
| `knowledge_point_ids` | 关联的知识点ID列表 |
| `typical_cases` | 典型案例（脱敏后的错题/提问原文，最多3条） |
| `severity` | 严重程度（高/中/低，由 LLM 根据频次和影响判定） |

**R5.4** 聚类完成后，系统应将结果存入 `AnalyticsReport` 表（`report_type = "problem_cluster"`），教师可随时回查历史聚类报告。

**R5.5** 如果 agentic 服务不可用，则系统应返回错误提示"AI 服务暂不可用，请稍后重试"，并在日志中记录失败原因。系统不崩溃。

**R5.6** 当教师查看班级反馈汇总时，系统应向模块2 查询该班学生的提交内容中包含的提问和反馈文本（非空 `feedback` 字段），按时间排序展示。

---

### R6 组：教学建议与干预

> 教师触发后，系统结合薄弱知识点、聚类结果、进度数据，通过 agentic 服务生成可操作的教学调整建议。

**R6.1** 当教师触发教学建议生成时，系统应汇聚以下数据发送至 agentic 服务 `/api/agent/teaching-suggestions`：
- 班级薄弱知识点列表（来自 R2.4 得分率排名）
- 最新共性问题聚类结果（来自 R5）
- 班级整体进度数据（来自 R3）
- 当前未解除的风险预警数量

**R6.2** agentic 返回的教学建议每项应包含：

| 字段 | 说明 |
|------|------|
| `suggestion_type` | 建议类型：`reteach`（重新讲解）/ `extra_material`（补充材料）/ `exercise`（增加练习）/ `pace_adjust`（调整进度）/ `individual_attention`（个别关注） |
| `content` | 具体建议内容（如"建议在下次课重新讲解'列表推导式'语法，可使用XX案例辅助"） |
| `target` | 建议指向的对象：`whole_class`（全班）/ `knowledge_point_id`（某知识点）/ `student_id`（某学生） |
| `urgency` | 紧急程度：高/中/低 |
| `based_on` | 建议依据的数据摘要（如"该知识点错题率 67%，涉及 23 名学生"） |

**R6.3** 当教师触发对某学生的干预建议时，系统应将该学生的画像（模块4）、成绩序列（模块3）、学习日志（模块2）、风险状态（模块5自身）发送至 agentic 服务，由 LLM 生成针对性的辅导建议。

**R6.4** 教师应能查看历史生成的所有教学建议记录，按时间排序。

**R6.5** 如果 agentic 服务不可用，则系统应返回错误提示，但不影响其他功能模块正常运行。

**R6.6** 系统不应自动执行任何教学干预操作（如自动发通知、自动调整任务等），所有建议仅供教师参考，执行权在教师。

---

### R7 组：报表导出

**R7.1** 当教师触发生成成绩报表时，系统应将 R2 的成绩分析数据导出为 Excel（.xlsx）文件，包含：
- Sheet1：学生成绩总表（学号/姓名/各任务得分/总分/排名）
- Sheet2：成绩分布统计（各分数段人数与比例）
- Sheet3：知识点得分率明细

**R7.2** 当教师触发生成综合分析报告时，系统应将当前班级的最新分析结果（成绩总览 + 进度总览 + 风险学生列表 + 薄弱知识点 + 聚类结果 + 教学建议）导出为 PDF 文件。

**R7.3** 系统应在导出请求后 10 秒内开始文件下载（数据量 < 100 学生）。

**R7.4** 系统应保留最近 30 天的导出记录，教师可在平台上重新下载历史导出文件。

---

### R8 组：游戏事件集成

> 模块5 不主动发游戏事件，但接收模块4 的回调并将游戏事件转化为教师可见的风险预警。

**R8.1** 模块5 应实现 `POST /api/risk-alerts` 接口，接收模块4 发送的游戏风险事件。

**R8.2** 当接收到 `hp_critical` 事件时，系统应自动创建 `RiskAlert`（`risk_type = "hp_critical"`, `risk_level = "high"`）。

**R8.3** 当接收到 `stuck_detected` 事件时，系统应自动创建 `RiskAlert`（`risk_type = "stuck"`, `risk_level = "medium"`），并在 `detail` 中包含卡顿的知识点ID和失败次数。

**R8.4** 模块5 应提供以下方法供模块4 调用：

```java
// 查询班级的风险预警列表（模块4 用于判断是否重复生成预警）
List<RiskAlert> getClassRiskAlerts(String classId);

// 查询某学生的当前风险状态（可能为 null）
RiskStatus getStudentRiskStatus(String studentId);
```

**R8.5** 当模块4 查询学生风险状态时，系统应返回该生当前所有未解除预警的风险类型列表和最高风险等级。

## 四、核心实体

### 4.1 数据表

| 实体 | 表名 | 说明 | 关键字段 |
|------|------|------|---------|
| `Class` | `analytics_class` | 班级 | id (UUID), name, course_id (→ 模块1.Course), teacher_id, semester, created_at, updated_at |
| `AnalyticsReport` | `analytics_report` | 分析报告（缓存聚类/建议结果） | id (UUID), class_id, report_type (enum: problem_cluster / teaching_suggestion / score_analysis), data_json (JSON), generated_at |
| `RiskAlert` | `analytics_risk_alert` | 学习风险预警 | id (UUID), student_id (→ 模块4.Student), course_id (→ 模块1.Course), risk_type (enum), risk_level (enum: high/medium/low), detail (JSON), status (enum: active/resolved), created_at, resolved_at, resolved_by |
| `TeachingSuggestion` | `analytics_teaching_suggestion` | 教学建议 | id (UUID), class_id, course_id, suggestion_type (enum), content (TEXT), target_type, target_id, urgency (enum), based_on (JSON), generated_at |

### 4.2 枚举定义

**risk_type**：
```
procrastination     — 任务拖延
low_score          — 连续低分
score_decline      — 成绩下滑
inactive           — 长期未登录
progress_lag       — 进度落后
hp_critical        — 游戏HP临界（模块4 推送）
stuck              — 游戏卡顿（模块4 推送）
```

**risk_level**：`high` / `medium` / `low`

**report_type**：`problem_cluster` / `teaching_suggestion` / `score_analysis`

**suggestion_type**：`reteach` / `extra_material` / `exercise` / `pace_adjust` / `individual_attention`

### 4.3 实体关系

```
Class (1) ────── (N) Student (via 模块4)
Class (1) ────── (N) AnalyticsReport
Class (1) ────── (N) TeachingSuggestion
Student (1) ──── (N) RiskAlert (student_id + course_id)
```

## 五、对外接口清单（REST API + Java Service）

### 5.1 REST API 完整列表

```
# -- 班级管理 --
POST   /api/classes                        → 创建班级
GET    /api/classes                        → 班级列表 ?teacher_id={id}
GET    /api/classes/{id}                   → 班级详情（含学生列表）
PUT    /api/classes/{id}                   → 修改班级信息
DELETE /api/classes/{id}                   → 删除班级（无学生时）
POST   /api/classes/{id}/enroll            → 添加学生到班级
DELETE /api/classes/{id}/students/{sid}    → 从班级移除学生

# -- 成绩分析 --
GET    /api/classes/{id}/scores            → 班级成绩总览
GET    /api/classes/{id}/score-trends      → 成绩趋势图表数据
         ?student_id={id}&time_range={start,end}&granularity={week|exam}
GET    /api/classes/{id}/score-distribution → 成绩分布统计
GET    /api/classes/{id}/weak-points       → 班级薄弱知识点排名

# -- 进度监控 --
GET    /api/classes/{id}/progress          → 班级整体学习进度
GET    /api/classes/{id}/task-completion   → 任务完成率详情
         ?task_id={id}

# -- 风险预警 --
GET    /api/classes/{id}/risk-alerts       → 班级风险学生列表
         ?status={active|resolved}&level={high|medium|low}
GET    /api/students/{id}/risk-status      → 某学生当前风险状态
POST   /api/classes/{id}/risk-detect       → 手动触发风险检测
PUT    /api/risk-alerts/{id}/resolve       → 标记预警为已处理

         body: { student_id, course_id, risk_type, detail_json }

# -- 共性问题 --
POST   /api/classes/{id}/problem-cluster   → 执行共性问题聚类分析（→ agentic）

# -- 教学建议 --
POST   /api/classes/{id}/teaching-suggestions → 生成教学调整建议（→ agentic）
GET    /api/classes/{id}/teaching-suggestions → 获取历史教学建议

# -- 干预建议 --
POST   /api/students/{id}/intervention     → 生成个别学生干预建议（→ agentic）

# -- 报表导出 --
POST   /api/classes/{id}/reports/export    → 导出成绩报表
         body: { format: "excel"|"pdf", report_type: "scores"|"full_analysis" }
GET    /api/reports/{id}/download          → 下载已生成的报表文件
```

## 七、模块间数据流

```
                    ┌──────────────────────────────────────┐
                    │           模块5：学情分析与教学决策     │
                    │                                      │
   模块1 ──────────→│  CourseID, KnowledgePointID           │
   模块2 ──────────→│  Submission, LearningLog, Progress    │────→ 前端（教师端仪表盘）
   模块3 ──────────→│  ScoreRecord, MistakeStats             │
   模块4 ──────────→│  StudentInfo, StudentProfile           │────→ 模块4（风险状态查询）
   模块4 ──事件──→  │  hp_critical, stuck, inactive         │
   agentic ←───────→│  风险检测, 问题聚类, 教学建议           │
                    └──────────────────────────────────────┘
```

**数据流动原则**：
- 模块5 **只读消费**模块1~4的数据，不反向写入
- 唯一的"写"操作是接收模块4的游戏事件并创建 RiskAlert
- 所有聚合计算在模块5内部完成，agentic 只做 LLM 推理

## 八、与爬塔游戏化的衔接

模块5 在游戏化体系中的角色是**接收方和教师展示层**：

| 游戏事件（模块4发出） | 模块5的响应 | 教师端展示 |
|---------------------|-----------|-----------|
| `hp_critical`（HP < 30） | 自动创建 RiskAlert(risk_type="hp_critical", level="high") | 塔灵预警面板红色高亮该学生 |
| `stuck_detected`（同一知识点失败≥3次） | 自动创建 RiskAlert(risk_type="stuck", level="medium") | 塔灵预警面板橙色标记 |
| 连续3天未登录 | 自动创建 RiskAlert(risk_type="inactive", level="medium") | 塔灵预警面板黄色标记 |

模块5 自身提供的游戏化相关功能（教师端）：
- **塔灵预警**：预警学生列表，按风险等级排序，展示"死亡热点地图"
- **战场复盘**：共性问题聚类结果 → 教师可看到"全班在哪些知识点'阵亡'最多"
- **排行榜**：消费模块4的排行榜数据，在教师端展示班级内的通关进度排名

## 十一、不做（明确排除）

以下功能**不在模块5 范围内**，防止范围蔓延：

1. ❌ **不持有学生/课程/任务/试题数据的写入权**：这些数据的增删改由模块1~4各自负责，模块5只做只读聚合
2. ❌ **不自动执行教学干预**：系统只生成建议和预警，不会自动发送通知、自动调整任务、自动联系学生。所有操作由教师手动触发
3. ❌ **不做独立的消息推送系统**：Phase 1-3 期间预警仅在教师端仪表盘内展示，不做邮件/短信/App Push。如需推送延后到 Phase 4 评估
4. ❌ **不做教师之间的协作/共享**：班级数据仅创建者可见，不做教师间的班级共享、协管
5. ❌ **不做实时聊天/即时通讯**：教师与学生之间的沟通不在此模块
6. ❌ **不做学生端学情展示**：学生端的学习分析页面由模块4（学生画像）负责，模块5 仅提供教师端
7. ❌ **不做跨课程对比分析**：所有分析以单个课程为单位，不做"Python课程 vs Java课程"的跨课对比
8. ❌ **不做自定义报表设计器**：报表格式固定，教师不可自定义拖拽生成
