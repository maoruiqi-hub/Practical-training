# 模块2：学习任务与过程跟踪 — 需求分析

> 一句话定位：定义"学习任务与过程跟踪模块"的功能需求，覆盖任务发布/管理/提交/状态记录/行为日志/进度查看/数据统计的全链路。
> 阅读前置：[../README.md](../README.md)、[../common/authoring-conventions.md](../common/authoring-conventions.md)
> 状态：草拟

---

## 1. 背景

学习任务与过程跟踪模块是 AI 智慧课程平台的教学活动中枢。教师通过该模块组织具体教学活动（发布任务、查看进度、分析数据），学生通过该模块完成课程任务，系统则将任务执行过程中的行为数据沉淀为学习日志，为其他模块（测评评价、学生画像、学情分析）提供数据来源。

当前项目中已有一版基础实现（LearningTask CRUD + TaskSubmission CRUD + Quiz答题系统），但缺少：
- 任务与章节/知识点的关联
- 多类型任务的差异化处理（视频类、阅读类、实践类等）
- 完整的状态机（未提交/已提交/逾期/待批改/已完成）
- 任务筛选、状态管理等管理功能
- 学习行为日志采集机制
- 综合的学习进度查看

---

## 2. 目标

1. 完善任务发布与管理功能，支持任务关联章节和知识点
2. 实现多类型任务的差异化处理（阅读、视频、测验、报告、实践等）
3. 建立完整的任务状态机，覆盖学生从查看到完成的全流程
4. 构建学习行为日志系统，统一采集学生在平台上的关键行为数据
5. 实现学习进度查看功能，学生可看个人进度，教师可看全班进度
6. 增强数据统计能力，输出完成率、平均时长、逾期率等指标

---

## 3. 功能描述（EARS 需求）

### R1 组：学习任务发布与管理（对应 3.2.1、3.2.2）

**R1.1** 教师登录后，系统应允许发布新任务，录入：任务名称、任务说明、所属课程、关联章节（可选）、关联知识点（可选）、任务类型、截止时间、提交方式、分值、评分规则（可选）、附件资源（可选）。

**R1.2** 当教师发布任务时，系统应校验必填字段（任务名称、课程、类型、截止时间、提交方式、分值），缺少任一必填字段则拒绝创建并给出明确提示。

**R1.3** 系统应支持以下任务类型：章节作业、试卷答题/测验、视频观看、PPT阅读、教材学习、课程报告、实验任务、实践项目。

**R1.4** 教师应能修改已发布任务的任意字段；修改后系统应记录修改时间。

**R1.5** 教师应能删除任务。如果任务已有学生提交，则系统应提示确认后再删除，删除后关联的提交记录不物理删除（保留数据）。

**R1.6** 系统应支持任务状态管理：草稿（仅教师可见）、已发布（学生可见可提交）、已关闭（学生可见但不可提交）。

**R1.7** 教师应能按课程、章节、任务类型、发布时间、截止时间筛选任务列表。

**R1.8** 学生登录后，应能查看所属课程的所有已发布任务列表，区分"待完成""已提交""已逾期"状态。

### R2 组：任务截止与提交设置（对应 3.2.4）

**R2.1** 教师发布任务时，可设置是否允许逾期提交。如果不允许，截止时间过后学生提交按钮应置灰并提示"已截止"。

**R2.2** 教师可设置提交次数限制（默认1次）。如果学生已达上限，应提示"已达最大提交次数"。

**R2.3** 教师可设置附件格式要求（如 `.pdf,.doc,.docx,.zip`）。学生上传不符合格式的文件时，系统应拒绝并提示允许的格式。

**R2.4** 系统应根据截止时间和提交状态，自动判定每个学生任务的状态为：未提交、已提交、逾期提交、待批改、已完成。

### R3 组：学生任务提交（对应 3.2.5）

**R3.1** 对于测验类任务，学生应在在线答题界面完成作答（单选/多选/填空/简答/编程），系统提交时将答案序列化为 JSON 存储。

**R3.2** 对于报告/文档类任务，学生应能上传 Word 或 PDF 文件；系统应校验文件格式符合教师设置的要求。

**R3.3** 对于实践/项目类任务，学生应能上传项目文件、代码压缩包或输入文字说明。

**R3.4** 对于视频/阅读类任务，学生无需手动提交；系统应根据行为日志自动判定完成状态。

**R3.5** 当学生提交任务时，系统应记录提交时间、提交次数（第几次提交）、是否逾期。

**R3.6** 如果在截止时间后提交且教师不允许逾期提交，系统应拒绝并提示"任务已截止，不允许逾期提交"。

**R3.7** 学生可在截止时间前修改自己的提交（如果未达提交次数上限），系统应保留提交历史。

### R4 组：任务完成状态记录（对应 3.2.6）

**R4.1** 系统应记录每名学生对每个任务的完成状态，包括：是否完成、完成时间、提交次数、是否逾期、任务得分、教师反馈。

**R4.2** 学生应能在任务页面查看自己对每个任务的状态和得分。

**R4.3** 教师应能在课程维度查看全班学生的任务完成情况矩阵（学生×任务），一眼识别未提交、逾期、已完成的学生。

### R5 组：学习行为日志采集（对应 3.2.7）

**R5.1** 系统应提供行为日志上报接口，前端在以下事件发生时调用：
- 视频：开始播放、暂停、跳转、播放完成
- PPT/PDF：打开浏览、翻页、关闭
- 测验：开始答题、提交答案
- 资源：下载、预览
- 报告：提交、重新提交
- 任务：查看任务详情

**R5.2** 每条行为日志应包含：用户ID、用户类型（student/teacher）、资源类型、资源ID、关联任务（可选）、关联知识点（可选）、动作类型、开始时间、停留时长（可选）、完成状态（可选）、操作结果（可选）。

**R5.3** 系统应提供日志查询接口，支持按用户、课程、动作类型、时间范围筛选。

**R5.4** 前端在视频播放时，应每隔30秒或暂停/跳转时上报一次播放进度日志。

### R6 组：学习过程数据统计（对应 3.2.8）

**R6.1** 系统应为学生提供个人统计：任务完成率（已完成数/总任务数）、平均得分、逾期次数、总学习时长。

**R6.2** 系统应为教师提供课程统计：各任务完成率、班级平均完成时长、逾期人数、各任务平均得分。

**R6.3** 系统应统计资源访问频次：各资源的查看次数、各视频的观看完成率。

**R6.4** 统计结果应支持可视化展示（柱状图、折线图、进度条）。

### R7 组：学习进度查看（对应 3.2.9）

**R7.1** 学生端应展示课程学习进度概览：任务完成进度条（已完成X/共Y个）、各任务状态列表、最近学习活动时间线。

**R7.2** 教师端应按课程展示全班学生进度总览表：每个学生的任务完成数、完成率、最后活跃时间、逾期次数。

**R7.3** 教师端应能识别并高亮标注进度落后（完成率<50%）和存在逾期（逾期≥2次）的学生。

## 4. 验收标准

| 编号 | 验收条件 |
|------|---------|
| AC1 | 教师能创建包含名称、课程、类型、章节、知识点、截止时间、提交方式、评分规则的任务 |
| AC2 | 任务支持草稿/已发布/已关闭三种状态的切换 |
| AC3 | 教师能按课程+类型+时间等多条件组合筛选任务 |
| AC4 | 学生端能按任务类型展示不同的提交界面（测验答题、文件上传、自动完成） |
| AC5 | 系统能正确判断每个学生任务的5种状态（未提交/已提交/逾期/待批改/已完成） |
| AC6 | 行为日志接口能正确记录并查询各类学习行为 |
| AC7 | 视频播放进度能被准确追踪且支持断点续播 |
| AC8 | 学生端能看到自己的课程进度（完成率+各任务状态） |
| AC9 | 教师端能看到全班学生×任务的完成矩阵 |
| AC10 | 统计数据（完成率、平均分、逾期率、学习时长）准确无误 |

## 5. 技术约束

- 后端：Java 17 + Spring Boot 3.5.15 + MyBatis-Plus
- 前端：Vue 3 + Element Plus + ECharts
- 数据库：TiDB Cloud (MySQL 兼容)
- 遵循现有项目包结构（`com.neu.CoursePlatform`）
- 遵循 `docs/architecture/模块接口与协作规范.md` 中模块2的接口契约
- 新增表遵循命名约定（`learning_behavior_log`）
- 文件上传复用已有 `FileStorageService`

## 6. 不做（明确排除）

- ❌ 不实现 AI 智能批改（属于模块3）
- ❌ 不实现学习风险预警（属于模块5，但模块2提供日志数据作为输入）
- ❌ 不实现学生画像/能力评分计算（属于模块4）
- ❌ 不实现知识图谱构建（属于模块1）
- ❌ 不实现成绩报表导出 Excel/PDF（属于模块5）
- ❌ 不实现题目管理和组卷功能（已有基础实现，属于模块3）
- ❌ 不修改现有鉴权机制
- ❌ 不在本阶段重构前端路由架构
