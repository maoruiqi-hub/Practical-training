原来的 surefire 插件 argLine 写死了 byte-buddy agent 路径，会导致 JaCoCo agent 无法加载。改为：

```xml
<argLine>${argLine} -javaagent:${settings.localRepository}/net/bytebuddy/byte-buddy-agent/1.17.8/byte-buddy-agent-1.17.8.jar</argLine>
```

在 `-javaagent` 前加了 `${argLine}` 占位符，让 JaCoCo 能通过 `prepare-agent` 注入自己的 agent。

## 三、测试技术方案

### 为什么不直接用 Mockito

项目已有的 `ProfileServiceImplTest` 用了 Mockito，但 Mockito 依赖 byte-buddy，和项目 surefire 配置的 byte-buddy-agent 版本有冲突，在 JDK 23 下运行时报 `MockMaker` 加载失败。

### 方案一：动态代理（用于接口类 Mapper/Service）

参考项目自带的 `Module2ServiceTest.java` 的写法，用 `java.lang.reflect.Proxy` 动态生成接口的模拟实现：

```java
TeacherMapper proxy = (TeacherMapper) Proxy.newProxyInstance(
    TeacherMapper.class.getClassLoader(),
    new Class<?>[]{TeacherMapper.class},
    (p, method, args) -> {
        switch (method.getName()) {
            case "selectByUsername": return store.findByUsername((String) args[0]);
            case "insert": store.put(...); return 1;
        }
    });

// 注入到 ServiceImpl 的 baseMapper 字段（递归查找父类）
setBaseMapper(service, proxy);
```

### 方案二：匿名子类（用于具体类 Component/Service）

AI 模块的 `DifyClient`、`AgenticClient`、`DifyKnowledgeService` 是具体类（`@Component`、`@Service`），不能用 `Proxy`。改用匿名子类覆写方法：

```java
DifyClient mockClient = new DifyClient() {
    @Override
    public boolean isConfigured() { return true; }

    @Override
    public DifyResponse sendChatMessage(String query, String userId) {
        return DifyResponse.success("Mock response: " + query);
    }
};
```

### 注入 baseMapper 的坑

MyBatis-Plus 的 `baseMapper` 字段不在 `ServiceImpl` 中，而是在父类 `BaseServiceImpl` 里，普通反射 `getDeclaredField` 找不到。需要递归遍历类层级：

```java
static void setBaseMapper(Object service, Object mapper) throws Exception {
    Class<?> clazz = service.getClass();
    while (clazz != null) {
        try {
            Field f = clazz.getDeclaredField("baseMapper");
            f.setAccessible(true);
            f.set(service, mapper);
            return;
        } catch (NoSuchFieldException e) {
            clazz = clazz.getSuperclass();
        }
    }
}
```

## 六、遇到的问题和解决

| 问题 | 解决方案 |
|------|---------|
| Mockito 初始化失败（byte-buddy 版本冲突） | 改用 Java 动态代理 + 匿名子类，与项目现有测试风格一致 |
| `AgenticClient` 是具体类，`Proxy` 不能 mock | 改用匿名子类 `new AgenticClient(...) { @Override ... }` |
| `knowledgeExtract/chat/grade/recommend/riskDetect` 无 mock 模式分支 | 改为 dify 模式测试，用 mock DifyClient 返回成功响应 |
| `baseMapper` 字段反射不到 | 递归遍历 ServiceImpl 的父类层级 |
| JaCoCo agent 不生效（argLine 被覆盖） | 在 surefire argLine 中加 `${argLine}` 占位符 |
| JaCoCo 报告路径 C 盘 vs D 盘 | 项目的 WebConfig 硬编码了 C 盘路径，与当前 D 盘不符 |
| `var` 关键字导致编译错误 | 部分场景下 `var` 类型推断不兼容，显式写 `Class<?>` |
| Long vs Integer 断言失败 | `Math.round()` 返回 `long`，断言需要用 `assertEquals(L, ...)` |
| JDK 23 + 旧版 Mockito 不兼容 | 业务测试不用 Mockito，AI 模块测试用匿名子类替代 |
| JDK 21+ Mockito inline mock maker 不兼容 | 添加 `src/test/resources/mockito-extensions/org.mockito.plugins.MockMaker` 配置 `mock-maker-subclass` |
| MyBatis-Plus AbstractRepository 调用 `insertOrUpdate` | 动态代理需额外处理 `insertOrUpdate` 方法，返回 `Boolean` 而非 `Integer` |

## 二、测试技术方案

### API 测试：vi.mock('axios') + 真实导入

```typescript
const mockAxiosInstance = vi.hoisted(() => ({
  get: vi.fn(() => Promise.resolve({ data: {} })),
  post: vi.fn(() => Promise.resolve({ data: {} })),
  put: vi.fn(() => Promise.resolve({ data: {} })),
  delete: vi.fn(() => Promise.resolve({ data: {} }))
}))

vi.mock('axios', () => ({
  default: { create: vi.fn(() => mockAxiosInstance) }
}))

// 导入真实 API 模块，所有函数调用都经过 mockAxiosInstance
import { studentLogin, getCourseByCode, ... } from '../index'
```

**优点**：真实导入被测模块 → 生成覆盖率报告；`vi.hoisted()` 确保 mock 在 import 前生效。

### 路由测试：逻辑提取

Vue Router 的 `createRouter`/`createWebHistory` 需要完整 jsdom 环境且 mock 复杂。采用提取纯函数方式：
- 提取 `studentRoomRedirects` 映射表直接测试
- 提取 `beforeEachGuard` 函数逻辑，用 `vi.stubGlobal('localStorage', ...)` 模拟
- 路由表结构用静态数组验证

### 游戏资源测试：vi.mock 替代 require()

源文件使用 webpack `require()` 加载图片，Vitest/Vite 不支持。采用 `vi.mock` 提供等效数据结构验证。
