```xml
<plugin>
    <groupId>org.jacoco</groupId>

    <version>0.8.12</version>
</plugin>
```

### pom.xml — 修复 argLine 冲突

原来的 surefire 插件 argLine 写死了 byte-buddy agent 路径，会导致 JaCoCo agent 无法加载。改为：

```xml
<argLine>${argLine} -javaagent:${settings.localRepository}/net/bytebuddy/byte-buddy-agent/1.17.8/byte-buddy-agent-1.17.8.jar</argLine>
```

在 `-javaagent` 前加了 `${argLine}` 占位符，让 JaCoCo 能通过 `prepare-agent` 注入自己的 agent。

## 三、测试技术方案

### 为什么不直接用 Mockito

项目已有的 `ProfileServiceImplTest` 用了 Mockito，但 Mockito 依赖 byte-buddy，和项目 surefire 配置的 byte-buddy-agent 版本有冲突，运行时报 `MockMaker` 加载失败。

### 改用动态代理

参考项目自带的 `Module2ServiceTest.java` 的写法，用 `java.lang.reflect.Proxy` 动态生成 Mapper 的模拟实现：

```java
TeacherMapper proxy = (TeacherMapper) Proxy.newProxyInstance(
    TeacherMapper.class.getClassLoader(),
    new Class<?>[]{TeacherMapper.class},
    (p, method, args) -> {
        // 根据方法名分发到内存模拟逻辑
        switch (method.getName()) {
            case "selectByUsername": return store.findByUsername((String) args[0]);
            case "insert": store.put(...); return 1;
            // ...
        }
    });

// 注入到 ServiceImpl 的 baseMapper 字段（递归查找父类）
setBaseMapper(service, proxy);
```

### 注入 baseMapper 的坑

MyBatis-Plus 的 `baseMapper` 字段不在 `ServiceImpl` 中，而是在父类 `BaseServiceImpl` 里，普通反射 `getDeclaredField` 找不到。需要递归遍历类层级：

```java
static void setBaseMapper(Object service, Object mapper) throws Exception {
    Class<?> clazz = service.getClass();
    while (clazz != null) {
        try {
            Field f = clazz.getDeclaredField("baseMapper");
            f.setAccessible(true);
            f.set(service, mapper);
            return;
        } catch (NoSuchFieldException e) {
            clazz = clazz.getSuperclass();
        }
    }
}
```

## 六、遇到的问题和解决

| 问题 | 解决方案 |
|------|---------|
| Mockito 初始化失败（byte-buddy 版本冲突） | 改用 Java 动态代理，与项目现有测试风格一致 |
| `baseMapper` 字段反射不到 | 递归遍历 ServiceImpl 的父类层级 |
| JaCoCo agent 不生效（argLine 被覆盖） | 在 surefire argLine 中加 `${argLine}` 占位符 |
| JaCoCo 报告路径 C 盘 vs D 盘 | 项目的 WebConfig 硬编码了 C 盘路径，与当前 D 盘不符 |
| `var` 关键字导致编译错误 | 部分场景下 `var` 类型推断不兼容，显式写 `Class<?>` |
| Long vs Integer 断言失败 | `Math.round()` 返回 `long`，断言需要用 `assertEquals(L, ...)` |
