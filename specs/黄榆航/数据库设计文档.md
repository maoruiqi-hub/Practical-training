## 二、设计原则

### 2.1 ID 策略 — 双轨并存

| 策略 | 类型 | 适用表 |
|------|------|--------|
| **序列号** | `VARCHAR(64)` + `IdType.AUTO` | 核心业务表：`student`、`course`、`learning_task`、`task_submission`、`question`、`exam` 等 21 张 |
| **UUID v4** | `VARCHAR(36)` + `IdType.ASSIGN_UUID` | 分析/画像/游戏化表：`student_profile`、`analytics_risk_alert`、`competency_score`、`achievement` 等 13 张 |

序列号通过 PostgreSQL 序列生成：`CAST(nextval('seq_name') AS VARCHAR(64))`，实际存储值为 "1"、"1001" 等整数形式的字符串。

### 2.2 命名约定

- **SQL 层**：`snake_case`（如 `course_code`、`knowledge_point_id`、`student_no`）
- **Java 层**：`camelCase`（如 `courseCode`、`knowledgePointId`、`studentNo`）
- **MyBatis-Plus** 自动转换：`map-underscore-to-camel-case: true`
- **表命名**：未强制模块前缀，采用扁平命名空间（如 `learning_task` 而非 `module2_learning_task`）

### 2.3 无外键约束

全库 **不使用** `FOREIGN KEY ... REFERENCES` 语法。所有引用靠**约定字段名** + **应用层完整性校验**。

### 2.4 唯一索引保障业务规则

关键唯一索引：

| 索引名 | 约束 |
|--------|------|
| `uk_task_assignment_student_task` | 同一学生、同一任务只能分配一次 |
| `uk_knowledge_mastery` | 同一学生、同一课程、同一知识点只一条掌握度 |
| `uk_knowledge_relation` | 同一对知识点间不允许重复关系 |
| `uk_student_profile` | 同一学生、同一课程只一个画像 |
| `uk_class_student` | 同一学生、同一班级只一条注册记录 |

### 2.5 模块写权限隔离

每张表只归属一个模块写入，跨模块读取**必须通过目标模块的 Service**（不得直接查其他模块的 Mapper）：

```
模块1（课程体系）← 其他模块读取：KnowledgePointService、AbilityPointService
模块2（任务追踪）← 其他模块读取：TaskSubmissionService、BehaviorLogService
模块3（考核评测）← 其他模块读取：QuestionService、ExamService
模块4（学生画像）← 其他模块读取：ProfileService
模块5（学情分析）← 其他模块读取：ClassInfoService
```

## 三、全量 34 张表

### 模块 1 — 课程内容与知识体系（9 张）

| 表 | 主键 | ID 策略 | 关键引用字段 |
|----|------|---------|-------------|
| `course` | `course_code` | 序列 | `teacher_no` → `teacher.teacher_no` |
| `lesson` | `lesson_no` | 序列 | `course_code` → `course.course_code` |
| `course_resource` | `resource_id` | 序列 | `course_code`、`knowledge_point_id` |
| `knowledge_point` | `knowledge_point_id` | 序列 | `course_code`、`lesson_no` |
| `knowledge_relation` | `relation_id` | 序列 | `course_code`、`from_knowledge_point_id`、`to_knowledge_point_id` |
| `ability_point` | `ability_point_id` | 序列 | `course_code` → `course.course_code` |
| `ability_knowledge_point` | `id` | 序列 | `ability_point_id` + `knowledge_point_id`（多对多关联） |
| `knowledge_extraction_candidate` | `candidate_id` | 序列 | `course_code`、`resource_id` |
| `course_game_config` | `id` | UUID | `course_id` → `course`（爬塔模式开关 `game_mode_enabled`） |

**关系说明**：
- `knowledge_point` 与 `ability_point` 通过 `ability_knowledge_point` 表多对多关联
- `knowledge_relation` 记录知识点之间的前置依赖关系（`from → to`）
- `knowledge_extraction_candidate` 存储从资源中 AI 抽取的待审核知识点

### 模块 2 — 学习任务与过程追踪（5 张）

| 表 | 主键 | ID 策略 | 关键引用字段 |
|----|------|---------|-------------|
| `learning_task` | `task_no` | 序列 | `course_code`、`lesson_no`、`knowledge_points`（JSON 数组） |
| `task_assignment` | `assignment_id` | 序列 | `task_no` + `student_no` + `course_code` |
| `task_submission` | `submission_id` | 序列 | `task_no` + `student_no` |
| `submission_answer` | `id` | 序列 | `submission_id` + `task_no` + `student_no` + `question_id` + `knowledge_point_id` |
| `task_question` | `id` | 序列 | `task_no` + `question_id` |

**关系说明**：
- `task_assignment` 是任务与学生的分配关系（从 `learning_task.target_student_no` 迁移而来）
- `task_submission` 记录每次提交；`status` 字段区分 `superseded`（被取代）和最新版本
- `submission_answer` 记录测验每道题的作答详情

### 模块 3 — 考核与评测（4 张）

| 表 | 主键 | ID 策略 | 关键引用字段 |
|----|------|---------|-------------|
| `question` | `question_id` | 序列 | `course_code`、`lesson_no`、`knowledge_point_id` |
| `exam` | `exam_id` | 序列 | `course_code`、`task_no` |
| `exam_question` | `id` | 序列 | `exam_id` + `question_id` + `knowledge_point_id` |
| `submission_ai_review` | `review_id` | 序列 | `submission_id` + `task_no` + `student_no` |

**关系说明**：

### 模块 4 — 学生画像与个性化推荐（10 张，含 user 表）

| 表 | 主键 | ID 策略 | 关键引用字段 |
|----|------|---------|-------------|
| `student` | `student_no` | 序列 | 独立用户实体 |
| `teacher` | `teacher_no` | 序列 | 独立用户实体 |
| `student_profile` | `id` | UUID | `student_no` + `course_code` |
| `knowledge_mastery` | `mastery_id` | UUID | `student_no` + `course_code` + `knowledge_point_id` |
| `knowledge_point_floor_status` | `id` | UUID | `student_id` + `course_id` + `knowledge_point_id` |
| `competency_score` | `id` | UUID | `student_no` + `course_code` + `ability_point_id` |
| `competency_score_history` | `id` | UUID | `student_no` + `course_code` + `ability_point_id` |
| `growth_history` | `id` | UUID | `student_no` + `course_code` |
| `recommendation` | `id` | UUID | `student_no` + `course_code` |
| `achievement` | `id` | UUID | `student_no` + `course_code` |

**关系说明**：
- `student_profile` 是学生-课程维度的画像，1 学生 × N 课程

### 模块 5 — 学习分析与教学决策（5 张）

| 表 | 主键 | ID 策略 | 关键引用字段 |
|----|------|---------|-------------|
| `learning_behavior_log` | `log_id` | 序列 | `user_id`、`task_no` |
| `analytics_class` | `id` | UUID | `course_id` + `teacher_id` |
| `analytics_class_student` | `id` | 序列 | `class_id` + `student_id` |
| `analytics_risk_alert` | `id` | UUID | `student_id` + `course_id` |
| `analytics_report` | `id` | UUID | `class_id` |
| `analytics_teaching_suggestion` | `id` | UUID | `class_id` + `course_id` |

**关系说明**：
- `analytics_class` 是教师创建的班级实体（注意：项目中学生表字段为 `class_name`，与这里的 `analytics_class` 是两套体系）
- `learning_behavior_log` 的 `user_id` 可以是学生或教师，有 `task_no` 的日志可通过 `learning_task.course_code` 关联到课程
- `analytics_risk_alert` 存储风险检测结果（长期未登录、进度落后、成绩下滑等）
- `analytics_teaching_suggestion` 和 `analytics_report` 暂无对应 Java 实体（实体待创建）

## 四、核心关系枢纽

整个数据库通过 **5 个共享键** 串联所有表：

```
                    ┌─────────────────┐
                    │     course       │
                    │  (course_code)   │ ←── 被 20+ 张表引用，是第一枢纽键
                    └────────┬────────┘
          ┌─────────────────┼─────────────────────┐
          ▼                 ▼                      ▼
   ┌──────────────┐  ┌──────────────┐  ┌──────────────────┐
   │    lesson    │  │knowledge_point│  │  learning_task   │
   │ (lesson_no)  │  │  (kp_id)     │  │   (task_no)      │
   └──────────────┘  └──────┬───────┘  └────────┬─────────┘
                             │                    │
              ┌──────────────┤            ┌───────┴──────────┐
              ▼              ▼            ▼                  ▼
        question      ability_point   task_           task_submission
        exam_question competency_     assignment      submission_ai_
        submission_   score                           review
        answer                                        learning_
                                                      behavior_log

                    ┌─────────────────┐
                    │    student      │
                    │  (student_no)   │ ←── 被 13+ 张表引用，第二枢纽键
                    └────────┬────────┘
          ┌─────────────────┼─────────────────────┐
          ▼                 ▼                      ▼
   task_assignment    task_submission    analytics_risk_alert
   student_profile    competency_score   achievement
   knowledge_mastery  recommendation     knowledge_point_floor_status
   growth_history     submission_answer
```

### 五键用途总结

| 键 | 主要用途 | 被引用次数 |
|----|---------|----------|
| `course_code` | 课程粒度的资源、知识、任务、考核、画像、分析 | 20+ |
| `student_no` | 学生粒度的分配、提交、画像、掌握度、风险 | 13+ |
| `task_no` | 任务粒度的分配、提交、评阅、行为日志 | 7 |
| `knowledge_point_id` | 知识点粒度的资源、关系、掌握度、题目 | 6+ |
| `lesson_no` | 课时粒度的知识点、任务、题目 | 3 |

## 五、跨表查询（自定义 Mapper XML）

| Mapper XML | 主要 JOIN |
|-----------|----------|
| `TaskAssignmentMapper.xml` | `task_assignment` **INNER JOIN** `learning_task` — 获取学生已分配任务（含课程、类型、状态过滤） |
| `BehaviorLogMapper.xml` | 条件 **INNER JOIN** `learning_task`（有 `course_id` 时）— 按课程过滤行为日志 |
| `QuestionMapper.xml` | `question` **LEFT JOIN** `knowledge_point` — 按知识点名称搜索题目 |
| `ClassInfoMapper.xml` | `analytics_class_student` **JOIN** `student` — 按班级获取学生列表及班级增删操作 |
| `RiskAlertMapper.xml` | **IN** 子句限定班级学生集合 — 按班级查询活跃风险预警 |

其余 Mapper XML（`CourseMapper`、`KnowledgePointMapper`、`LearningTaskMapper`、`StudentMapper`、`TeacherMapper`、`TaskSubmissionMapper` 等）均使用单表查询 + MyBatis-Plus 内置 `BaseMapper` 方法，无多表 JOIN。

## 七、已知问题与注意事项

1. **profile 实体类型不匹配**：`StudentProfile`、`CompetencyScore` 等 Java 实体中 `studentNo`/`courseCode` 声明为 `Integer`，但 SQL 列定义为 `VARCHAR(64)`，存在历史遗留不一致。

2. **两套班级体系**：`student.class_name`（学生表字符串字段）与 `analytics_class`（模块5班级实体）是不同的概念，当前 `class_id` 参数兼容映射到 `student.class_name` 查询。

3. **`learning_task.knowledge_points`** 是反范式设计，存储 JSON 数组而非标准外键，方便任务定义时嵌入知识点列表。

4. **`analytics_report` 和 `analytics_teaching_suggestion`** 表存在但无对应 Java 实体类——共性问题聚类和教学建议的持久化尚未完全打通。

5. **`IdType.AUTO` 实际行为**：Java 侧标记 `AUTO`，但 MyBatis-Plus 实际依赖数据库序列生成（通过在 SQL INSERT 中调用 `nextval`），不是数据库自增列。
