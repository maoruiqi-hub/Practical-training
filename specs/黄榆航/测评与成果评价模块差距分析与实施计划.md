# 测评与成果评价模块差距分析与实施计划

> 一句话定位：本文对照 3.3 测评与成果评价模块最新需求，盘点当前代码实现差距，并给出后续补齐计划。
> 阅读前置：[`../README.md`](../README.md)、[`../项目需求.md`](../项目需求.md)、[`../common/authoring-conventions.md`](../common/authoring-conventions.md)
> 状态：规划中。当前代码已实现题库、基础组卷、在线测验和客观题规则评阅，但知识图谱关联、智能评价、错题分析仍未完整实现。

## 1. 模块范围

测评与成果评价模块负责“如何评价学生学习成果”，覆盖题库管理、试卷生成、在线测验、客观题批改、主观成果评价和错题分析。该模块产生测评数据和评价结果，并为学生画像、学习推荐、教师学情分析提供基础数据。

## 3. 需求逐项差距分析

### 3.3.1 题库管理

**理想目标**

教师可以维护课程题库，包括试题新增、修改、删除、查询和分类管理。题库可按照课程、章节、知识点、题型和难度进行分类。

**当前已实现**

- 系统已支持题目新增、修改、删除。
- 系统已支持按课程查询题目：`GET /question/course/{courseCode}`。
- 系统已支持按课时查询题目：`GET /question/lesson/{lessonNo}`。
- 系统已支持按题干和知识点搜索题目：`GET /question/search?keyword=`。
- 题目实体已包含 `courseCode`、`lessonNo`、`knowledgePoint`、`type`、`difficulty`。

**差距**

- 题库管理页仍存在课程编号默认值问题，当前默认课程偏向 `1`，多课程场景不完整。
- 题库管理页缺少多条件筛选面板，不能直接按课程、章节、知识点、题型、难度组合过滤。
- 章节、知识点、难度目前只是字段，没有独立分类维护界面。

**补齐计划**

- 增加题库管理页课程选择器，教师默认只显示自己授课课程。
- 增加分类筛选栏：课程、章节、知识点、题型、难度。
- 后端新增组合筛选接口，避免前端只做本地过滤。

### 3.3.2 多题型试题管理

**理想目标**

系统支持选择题、填空题、简答题、编程题等多种题型，不同题型对应不同学习目标。

**当前已实现**

- 系统已支持 `single`、`multi`、`fill`、`essay`、`program` 五类题型。
- 在线测验页已支持选择题、填空题、简答题、编程题答题输入。
- 客观题自动评阅覆盖单选、多选、填空。
- 简答题和编程题进入教师复核。

**差距**

- 编程题目前只是文本输入，没有代码运行、测试用例、语言选择和判题结果。
- 多选题答案目前依赖逗号分隔文本，缺少标准化答案结构。
- 简答题和编程题评分维度没有结构化保存。

**补齐计划**

- 编程题增加字段：语言、时间限制、内存限制、测试用例、参考代码、评分说明。
- 选择题选项和答案改为结构化 JSON，减少文本解析歧义。
- 简答题和编程题增加评分维度配置。

### 3.3.3 试题知识点关联

**理想目标**

教师可将试题与课程知识图谱中的知识点关联。学生完成测验后，系统可依据知识点统计错题和得分情况，判断学生具体知识点掌握情况。

**当前已实现**

- 题目已有 `knowledgePoint` 文本字段。
- 搜索和组卷可使用 `knowledgePoint`。

**差距**

- 尚未实现知识点实体表。
- 尚未实现知识图谱节点和边关系。
- 试题没有关联真实知识点 ID，只保存文本。
- 测验提交后没有生成知识点维度得分和错题统计。

**补齐计划**

- 新增 `knowledge_point` 表，保存知识点 ID、名称、课程、章节、描述。
- 新增 `knowledge_edge` 表，保存知识点依赖关系。
- 将 `question.knowledge_point` 升级为 `knowledge_point_id`，保留文本字段作为展示冗余或迁移字段。
- 提交测验后生成学生知识点掌握记录。

### 3.3.4 试题难度等级设置

**理想目标**

教师可为试题设置基础题、中等题、提高题或综合题等难度等级，难度用于组卷和学习推荐。

**当前已实现**

- `Question.difficulty` 已支持 1~5 数值难度。
- 组卷支持 `difficultyMin` 和 `difficultyMax`。
- 难度平衡策略会按难度轮询抽题。

**差距**

- 前端没有把 1~5 明确映射为“基础题/中等题/提高题/综合题”。
- 难度平衡只是轮询抽题，不支持教师配置难度比例。
- 学习推荐尚未使用难度数据。

**补齐计划**

- 增加难度枚举展示：基础、较易、中等、提高、综合。
- 组卷请求支持难度比例，例如基础 40%、中等 40%、提高 20%。
- 学生薄弱知识点推荐时结合题目难度。

### 3.3.5 随机组卷

**理想目标**

系统支持从指定题库范围内随机抽题生成试卷，用于日常练习或快速测试。

**当前已实现**

- 后端支持 `strategy=random`。
- 前端发布在线测验时可点击“生成试卷”自动勾选题目。

**差距**

- 当前不保存“试卷版本”，每次生成只是绑定一组题目。
- 当前不支持同一测验对不同学生生成不同随机卷。
- 符合条件题目不足时会返回少于目标数量的题，没有强提醒。

**补齐计划**

- 增加生成结果校验，题量不足时明确提示。
- 设计 `paper`、`paper_question` 表，支持试卷版本保存。
- 若后续需要个性化随机卷，再增加学生维度试卷实例。

### 3.3.6 按知识点组卷

**理想目标**

教师可选择一个或多个知识点生成专项测试卷。

**当前已实现**

- 后端支持 `strategy=knowledge`。
- 前端支持多选知识点并生成试卷。

**差距**

- 知识点来自当前题库文本去重，不是知识图谱节点。
- 当前按知识点轮询抽题，不支持每个知识点指定题量。
- 没有章节测试模板或薄弱知识点专项训练入口。

**补齐计划**

- 知识点选择改为来自知识图谱节点。
- 组卷请求支持 `knowledgePointCounts`，可指定每个知识点题量。
- 学情分析模块输出薄弱知识点后，可一键生成专项练习。

### 3.3.7 按难度平衡组卷

**理想目标**

系统支持按照基础题、中等题、提高题等比例生成难度平衡试卷。

**当前已实现**

- 后端支持 `strategy=difficulty`，按难度分组轮询抽题。
- 前端可选择难度范围。

**差距**

- 当前没有比例配置。
- 当前没有固定总分控制。
- 当前没有题型和难度的二维约束，例如“单选 5 道，其中基础 3 道、中等 2 道”。

**补齐计划**

- 组卷请求增加 `difficultyRatios`。
- 组卷请求增加目标总分 `targetScore`。
- 后端组卷算法支持题型、知识点、难度、分值多约束。

### 3.3.8 学生报告、简答题和论文智能评价

**理想目标**

系统可调用 agentic 服务，对 Word、PDF 报告、论文或简答题回答进行辅助评价。

**当前已实现**

- 教师可查看非客观题提交并手动复核。
- 简答题、编程题不会被自动客观判分。
- 文件上传基础能力已存在。

**差距**

- 尚未调用 agentic 服务。
- 尚未解析 Word/PDF 内容。
- 尚未形成智能评价结果结构。
- 尚未保存评价维度，例如内容完整性、知识点覆盖度、逻辑结构、表达规范、任务符合度。

**补齐计划**

- 新增 `agentic` 评价 API 契约。
- 后端提交详情增加“请求智能评价”入口。
- 新增 `submission_ai_review` 表，保存 AI 评分、维度评分、评价理由和风险提示。
- 教师最终确认成绩时，可参考但不强制采用 AI 分数。

### 3.3.9 学习成果修改建议生成

**理想目标**

系统在完成报告或简答题评价后生成修改建议，帮助学生完善学习成果。

**当前已实现**

- 教师可填写反馈。
- 系统可在客观题自动评阅后写入简单反馈文本。

**差距**

- 没有自动生成修改建议。
- 没有把建议按维度结构化。
- 学生端没有专门展示修改建议的页面。

**补齐计划**

- `submission_ai_review` 增加 `suggestions` 字段。
- 学生端提交详情页展示修改建议。
- 教师端复核页展示 AI 建议，并允许教师编辑后发布给学生。

### 3.3.10 学生错题汇总分析

**理想目标**

系统对学生测验错题进行汇总，统计不同题目、知识点、题型的错误情况，服务个人复习和班级学情分析。

**当前已实现**

- 客观题可判断对错。
- 评阅详情里可展示学生答案和正确答案。

**差距**

- 没有持久化每道题的作答明细。
- 没有错题本页面。
- 没有知识点、题型、题目维度的错题统计接口。
- 没有班级维度共性错题分析。

**补齐计划**

- 新增 `submission_answer` 表，保存每道题的作答、是否正确、得分、知识点和题型。
- 新增学生错题本接口和页面。
- 新增教师端错题分析接口，按题目、知识点、题型聚合错误率。
- 将错题统计输出给学情分析和学习推荐模块。

## 4. 建议数据模型增量

| 表 | 用途 | 优先级 |
|----|------|--------|
| `knowledge_point` | 知识点实体，替代纯文本知识点 | P1 |
| `knowledge_edge` | 知识图谱边关系 | P2 |
| `paper` | 试卷版本信息 | P1 |
| `paper_question` | 试卷题目快照和顺序 | P1 |
| `submission_answer` | 学生逐题作答明细 | P0 |
| `submission_ai_review` | AI 主观评价结果和修改建议 | P2 |

## 5. 迭代实施计划

### P0：修正测评数据基础

- 新增 `submission_answer`，提交在线测验时保存逐题作答明细。
- 客观题评阅结果落库，支持错题统计。
- 题库管理页补齐课程、章节、知识点、题型、难度组合筛选。
- 组卷题量不足时阻止保存或提示教师确认。

### P1：完善试卷与分类能力

- 已新增 `paper` 和 `paper_question`，将组卷结果保存为试卷版本。
- 已支持固定总分、按题型数量、按知识点数量组卷。
- 已支持难度平衡比例配置。
- 已将题库页和测验组卷页的难度展示从数字升级为语义标签。

### P2：接入知识图谱和智能评价

- 已建立知识点实体和知识点关系。
- 已支持题目关联知识点 ID，并保留知识点名称用于展示兼容。
- 已建立主观提交辅助评价链路，支持通过环境变量接入 agentic 服务；未配置或调用失败时使用本地规则评价兜底。
- 已生成结构化维度评分和修改建议，教师可在复核页查看并采用到反馈。

### P3：学情分析与推荐联动

- 学生端增加错题本和知识点掌握视图。
- 教师端增加班级共性错题和知识点薄弱项统计。
- 将错题分析、知识点掌握、难度表现输出给学习推荐模块。

## 6. 验收标准

| 编号 | 验收标准 |
|------|----------|
| A1 | 教师可按课程、章节、知识点、题型、难度组合筛选题库。 |
| A2 | 教师可新增、编辑、删除单选、多选、填空、简答、编程题。 |
| A3 | 在线测验提交后，系统保存每道题的学生答案、正确性、得分和知识点。 |
| A4 | 随机组卷、按知识点组卷、难度平衡组卷均可生成可保存的试卷版本。 |
| A5 | 客观题提交后可自动评阅，教师可查看系统评阅详情。 |
| A6 | 简答题、报告、论文可触发 AI 辅助评价，并保存维度评分和修改建议。 |
| A7 | 学生端可查看个人错题汇总，教师端可查看班级错题统计。 |

## 7. 明确不做

- P0 阶段不实现代码沙箱判题，只将编程题作为主观题复核。
- P0 阶段不实现完整知识图谱可视化，只先保留知识点字段和错题统计。
- AI 评价结果不直接覆盖最终成绩，教师仍拥有最终确认权。
