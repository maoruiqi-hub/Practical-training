# 学生端个性化题包策略 V4

## 1. 目标

学生端题包由后端统一生成、校验和持久化，前端只负责渲染后端返回的正式题包。题包必须同时满足以下目标：

1. 普通关聚焦当前知识点，不混入其他章节题目。
2. 精英关同时包含当前知识、同能力迁移和历史薄弱复练。
3. Boss 关承担课程综合考查，允许跨知识点组题。
4. 所有正式题目必须来自数据库，并携带可追溯的 `questionId` 和 `packId`。
5. 每个可答题关卡至少返回 3 道有效题目；不足时明确报错，不使用前端演示题。

## 2. 责任边界

### 2.1 后端

- 根据 `studentNo + runId + nodeId + mode` 生成唯一题包。
- 校验学生、路线、节点、课程和题目归属。
- 执行房间配额、难度排序、题型覆盖、近期避重和历史薄弱题选择。
- 保存题目 ID、策略版本、各来源数量及回退状态。
- 题包策略升级后自动淘汰旧版本题包。

### 2.2 前端

- 有 `runId + nodeId` 时，只请求并渲染后端正式题包。
- 不对正式题包再次按知识点过滤，也不自行截断题目数量。
- 题包加载失败时显示错误和重试入口。
- 不使用 `demo-*`、`diagnosis-demo-*` 等本地演示题参与正式结算。

## 3. 房间策略

### 3.1 诊断房

- 目标数量：3 道。
- 题目范围：仅当前节点知识点。
- 用途：确认进入本轮学习前对当前知识点的掌握情况。
- 题库不足 3 道：拒绝生成题包并提示教师补题。

### 3.2 普通战斗

- 目标数量：5 道。
- 最低数量：3 道。
- 题目范围：仅当前节点知识点。
- 不允许为了凑题从其他章节、同能力点或课程总题库补题。
- 当前知识点不足 5 道但不少于 3 道时，可以按实际数量生成，并记录 `quotaFallback=true`。

### 3.3 精英战

目标数量为 6 道，标准配额为：

| 来源 | 数量 | 说明 |
|------|------|------|
| 当前知识点 | 3 | 当前关卡的核心训练题 |
| 同能力点 | 2 | 与当前知识点绑定同一能力点的其他知识点题 |
| 历史薄弱 | 1 | 学生真实答错题，或其历史薄弱知识点中的题 |

历史薄弱题可以与当前知识点或同能力点重合，但其选入身份仍记为“历史薄弱复练”。例如学生刚在诊断房答错当前知识点的一道题，该题可以占用历史薄弱配额，不占用 3 道普通当前知识点配额。

配额不足时：

1. 只能从当前知识点、同能力点和真实历史薄弱题池补位。
2. 不允许从无关章节或整个课程题库随机补题。
3. 在策略元数据中返回 `quotaFallback=true`。
4. 补位后仍不足 3 道时拒绝生成题包。

### 3.4 Boss 战

- 目标数量：8 道。
- 使用课程综合题池，允许跨知识点选题。
- 优先覆盖多种知识点、题型和较高难度。
- 仍需避开本轮已大量出现的重复题，但综合复习需要时允许重用。

## 4. 排序与避重

每个候选池内部按以下因素排序：

1. 历史薄弱配额优先选择学生真实答错过的原题。
2. 优先选择本轮路线中尚未出现的题目。
3. 题目难度接近节点难度。
4. 优先保持客观题、主观题和编程题的合理覆盖。
5. 使用节点和模式作为稳定排序因子，避免同一题包无意义抖动。

避重不能破坏房间核心语义：

- 普通关不能为了避重引入其他知识点。
- 精英关不能为了避重丢失当前知识点或同能力点配额。
- 历史薄弱复练允许有目的地重复学生曾经答错的题。

## 5. 策略元数据

题包响应中的 `strategy` 至少包含：

```json
{
  "strategyVersion": 4,
  "selectionPolicy": "elite-3-current-2-same-ability-1-historical-weakness",
  "targetCount": 6,
  "currentKnowledgeCount": 3,
  "sameAbilityCount": 2,
  "historicalWeaknessCount": 1,
  "quotaFallback": false,
  "knowledgePointId": "1011"
}
```

策略名称：

- `diagnosis-current-kp-only`
- `battle-current-kp-only`
- `elite-3-current-2-same-ability-1-historical-weakness`
- `boss-comprehensive-course`

## 6. 缓存与失效

1. 题包以 `runId + nodeId + mode` 唯一标识。
2. 未完成评价时重复进入同一节点，应复用同一有效题包。
3. 题包的 `strategyVersion` 低于当前版本时自动失效并重建。
4. 题包引用的题目被删除或不再属于当前课程时，应判定题包失效并重建。
5. 结算时后端根据 `packId` 校验提交题目，不能只信任前端提交的题目 ID。

## 7. 验收标准

1. 诊断房返回 3 道当前知识点题。
2. 普通战斗返回 3 至 5 道当前知识点题，且不含其他知识点。
3. 数据充足时，精英战严格返回 3 道当前知识点、2 道同能力点、1 道历史薄弱题。
4. 精英战发生补位时必须返回 `quotaFallback=true`，且不得出现无关章节题。
5. Boss 返回 8 道课程综合题，并覆盖多个知识点。
6. 所有题目 ID 都能在数据库 `question` 表中找到。
7. 前端显示题目数与题包接口返回题目数一致。
8. 同一有效题包重复读取时 `packId` 和题目顺序保持稳定。

首次审计发现，第 8 关的“综合项目实战能力”只关联最终项目知识点，无法提供 2 道同能力点题。已在幂等初始化脚本中将该能力关联到第 14 至 17 课。脚本按“课程 + 能力名称”复用原能力点，只补充缺失映射，不重建学生能力分数。
