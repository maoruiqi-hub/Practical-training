# 诊断前置精英关卡与 AI 诊断数据链路修复计划

## 一、问题结论

当前问题不是单纯的前端显示错误，而是关卡流程和 AI 诊断输入数据链路同时存在偏差：

- 诊断房被前端当成了可以直接切换到 `BattleRoom` 的当前房间，等于给诊断房单独造了一个战斗房。
- 正确业务中，诊断房是精英关卡的前置判断器，不是独立战斗房。
- 诊断没全对时，系统不应该生成最终诊断报告，而应该自动跳转到其绑定的精英关卡。
- 诊断全对时，说明绑定精英关卡对玩家没有难度，应直接标记诊断房和对应精英关卡通关，并解锁下一个诊断关卡。
- 图中“未检测到答题记录，无法生成诊断”说明 AI 诊断生成时拿到的 `answers/answerSummary` 为空或结构无效；前端只是展示了后端或 AI 返回的结果。

## 二、正确业务流程

### 1. 诊断全对

1. 玩家进入精英关卡前置诊断房。
2. 诊断房答题全部正确。
3. 前端提交诊断记录到后端。
4. 后端确认 `diagnosisPassed=true`。
5. 后端标记：
   - 当前诊断节点 `cleared`。
   - 诊断节点绑定的精英节点 `cleared`。
6. 后端解锁下一个主线诊断节点。
7. 前端不进入战斗房，不生成精英战斗报告。
8. 前端展示“诊断全对，已跳过对应精英关卡”，随后刷新地图或进入轻量通过反馈。

### 2. 诊断未全对

1. 玩家进入精英关卡前置诊断房。
2. 诊断房答题未全对。
3. 前端提交诊断记录到后端。
4. 后端确认 `diagnosisPassed=false`。
5. 后端只标记诊断节点完成或保持可复盘状态，不标记精英节点通关。
6. 后端返回绑定精英节点：
   - `nextRoomType='elite'`
   - `nextNodeId`
   - `nextNode`
7. 前端自动切换到该精英节点并进入精英战斗。
8. 精英战斗结束后，前端提交精英关卡 `answerSummary`。
9. 后端用精英战斗答题记录复算正确率。
10. 后端基于精英战斗答题记录调用 AI 生成诊断报告。
11. 结算页展示精英关卡正确率、AI 诊断报告、能力雷达。

## 四、后端修改计划

### 1. 明确诊断节点与精英节点绑定关系

目标：

- 诊断节点必须通过 `parentNodeId` 或等价字段绑定一个精英节点。
- 诊断节点不能自己进入战斗。

实现：

1. 新增或整理方法：
   - `boundEliteNode(runId, diagnosisNode)`
   - 只允许返回 `roomType='elite'` 的节点。
2. 原有 `boundBattleNode` 容易把普通战斗、Boss、精英混在一起，需拆分：
   - `boundEliteNode`
   - `boundBattleNode`
   - `boundBossNode`
3. 生成路线时确保：
   - 诊断节点 `parentNodeId = eliteNode.nodeId`。
   - 诊断节点 `unlockAfterNodeId` 指向上一主线节点。
   - 精英节点初始为 `locked`，只有诊断未全对时变为 `available`。

### 2. 重写 `diagnoseNode` 的返回语义

诊断全对时：

```json
{
  "status": "perfect",
  "correctRate": 1,
  "diagnosisPassed": true,
  "eliteBypassed": true,
  "clearedEliteNodeId": "elite-node-id",
  "nextNode": {},
  "run": {}
}
```

诊断未全对时：

```json
{
  "status": "partial",
  "correctRate": 0.67,
  "diagnosisPassed": false,
  "eliteBypassed": false,
  "nextRoomType": "elite",
  "nextNodeId": "elite-node-id",
  "nextNode": {},
  "run": {}
}
```

关键规则：

- 诊断未全对时，`diagnoseNode` 不调用 `buildTowerDiagnosisReport`。
- 诊断未全对时，不返回最终 `diagnosis/report`。
- 诊断未全对时，不写入“最终 AI 诊断报告”。
- 诊断记录仍可保存到 attempt，但 `aiReportJson` 应为空或标记 `stage='diagnosis_gate'`，不能冒充最终报告。

### 3. 精英关卡结束后才生成最终 AI 诊断

修改 `completeNode`：

1. 只在 `node.roomType` 为 `elite`、`battle`、`boss` 时生成最终诊断报告。
2. 对精英关卡：
   - 从 `answerSummary` 中筛选 `source='elite_room'` 或 `source='battle_room'` 的记录。
   - 后端复算 `correctRate`。
   - 如果没有有效答题记录，返回失败态，不调用 AI。

返回示例：

```json
{
  "correctRate": 0.67,
  "correctRateSource": "answer_summary",
  "gradedCount": 3,
  "correctCount": 2,
  "aiReportStatus": "success",
  "diagnosis": {
    "summary": "...",
    "weaknesses": [],
    "recommendedAction": "...",
    "source": "real_ai"
  }
}
```

### 4. AI 输入校验，解决“未检测到答题记录”

新增方法：

- `validReportAnswers(request, requiredSource)`
- `validateAiReportInput(answers, stage)`

校验规则：

- `answers` 必须是数组。
- 至少一条记录满足：
  - `answered=true`
  - `studentAnswer` 非空
  - `type` 非空
  - `correct` 为布尔值
  - `questionId` 非空
  - `source` 为 `elite_room` 或 `battle_room`
- 如果是精英结算报告，必须至少有一条 `source='elite_room'` 或兼容的 `source='battle_room'` 记录。

失败返回：

```json
{
  "aiReportStatus": "failed",
  "aiAvailable": false,
  "reportSource": "invalid_answer_summary",
  "errorMessage": "未检测到精英关卡答题记录，无法生成 AI 诊断。",
  "retryable": false,
  "diagnosis": null
}
```

注意：

- 这个错误由后端明确返回，不能让 AI 自己猜“未检测到答题记录”。
- 无效输入时不调用 AI。
- 前端显示失败态，但不把它当 AI 诊断方案。

### 5. AI prompt 调整

`AgenticClient` 的 `tower-diagnosis-report` prompt 增加约束：

- 输入为空时不要自行编造诊断。
- 只根据 `answers/wrongAnswers/correctRate/stage/roomType` 输出诊断。
- 输出 JSON 必须包含：
  - `summary`
  - `weaknesses`
  - `recommendedAction`
  - `reviewFocus`
  - `source`

但输入是否为空由后端先判断，不能依赖 prompt 兜底。

## 五、前端修改计划

### 1. `DiagnosisRoom.vue`

目标：

- 诊断房只负责诊断。
- 不再提供“直接进入战斗”按钮。
- 答完题自动提交完整诊断记录。

修改：

1. 删除底部 `scene-tools` 中的“直接进入战斗”。
2. `finishDiagnosis()` 中继续 emit `diagnosed`，但补全每条记录字段。
3. `answerSummary()` 输出格式改为：

```js
{
  questionId,
  stem,
  studentAnswer,
  correctAnswer,
  correct,
  answered,
  skipped: false,
  autoGradable,
  knowledgePointId,
  abilityPointId,
  type,
  source: 'diagnosis_room'
}
```

### 2. `FloorView.vue`

目标：

- 不再把诊断房本地切换成战斗房。
- 根据后端 `diagnoseNode` 返回值决定跳过精英或进入绑定精英节点。

修改 `handleDiagnosed`：

1. 收到诊断结果后，必须先调用 `diagnoseTowerNode`。
2. 如果 `payload.eliteBypassed === true`：
   - 不进入 `BattleRoom`。
   - 刷新 run/map/profile。
   - 展示“诊断全对，已跳过对应精英关卡”。
3. 如果 `payload.nextRoomType === 'elite'`：
   - 将 `activeNode` 或 `node` 更新为 `payload.nextNode`。
   - 将当前 `nodeId` 切换为精英节点 ID。
   - `phase='battle'`，但此时进入的是精英节点，不是诊断节点自己的战斗。
4. 如果后端没有返回绑定精英节点：
   - 显示明确错误：“未找到该诊断房对应的精英关卡”。
   - 不进入战斗。

### 3. `BattleRoom.vue`

目标：

- 精英关卡答题记录完整传给后端。
- 正确率口径只统计精英关卡实际结算过的题。

修改：

1. 根据 `roomType` 设置答题记录来源：
   - `elite` -> `source: 'elite_room'`
   - `boss` -> `source: 'boss_room'`
   - 普通战斗 -> `source: 'battle_room'`
2. `answerRecords` 中保留：
   - `answered`
   - `autoGradable`
   - `correct`
   - `studentAnswer`
   - `correctAnswer`
   - `type`
   - `source`
3. `battle-end` 传出 `answerSummary: answerRecords`。

### 4. 结算与诊断卡片状态

结算页诊断卡片改为三态：

- `loading`：精英关卡已结束，AI 诊断生成中。
- `success`：显示真实 AI 报告。
- `failed`：显示后端明确错误，例如“未检测到精英关卡答题记录，无法生成 AI 诊断”，并提供重试或返回地图。

注意：

- 诊断未全对后跳转精英关卡期间，不显示最终诊断报告。
- 诊断全对跳过精英时，可以显示轻量通过反馈，但不显示“精英战斗正确率”。
- 精英结算页正确率必须来自精英战斗记录，不使用诊断房正确率。

## 六、接口契约

### 1. `POST /diagnose`

请求：

```json
{
  "correctRate": 0.67,
  "status": "partial",
  "answers": [
    {
      "questionId": "q1",
      "studentAnswer": "A",
      "correctAnswer": "B",
      "correct": false,
      "answered": true,
      "autoGradable": true,
      "type": "single",
      "source": "diagnosis_room"
    }
  ],
  "packId": "pack-id"
}
```

响应：

- 全对：返回 `eliteBypassed=true`。
- 未全对：返回 `nextRoomType='elite'` 和 `nextNode`。
- 不返回最终 AI 诊断报告。

### 2. `POST /complete`

请求：

```json
{
  "result": "failed",
  "correctRate": 0.67,
  "cleared": false,
  "roomType": "elite",
  "hpLeft": 30,
  "packId": "pack-id",
  "answerSummary": []
}
```

后端必须：

- 校验 `answerSummary` 有效。
- 复算精英正确率。
- 有效才调用 AI。
- 无效则返回 `aiReportStatus='failed'`，不调用 AI。

## 七、测试计划

### 1. 后端单元测试

新增 `TowerRunServiceImplDiagnosisEliteFlowTest`：

- 诊断全对：
  - 诊断节点 cleared。
  - 绑定精英节点 cleared。
  - 下一个诊断节点 available。
  - 不调用 AI 生成精英战斗报告。
- 诊断未全对：
  - 返回 `nextRoomType='elite'`。
  - 返回绑定精英节点。
  - 精英节点 available。
  - 不生成最终 AI 报告。

新增 `TowerRunServiceImplAiReportInputTest`：

- 精英 complete 时 `answerSummary=[]`：
  - 返回 `aiReportStatus='failed'`。
  - `reportSource='invalid_answer_summary'`。
  - 不调用 AI。
- 精英 complete 时 `answerSummary` 有有效记录：
  - 调用 AI。
  - 返回 `aiReportStatus='success'`。
- 诊断房 answers 不应作为精英结算正确率来源。

### 2. 前端验证

- 诊断全对：
  - 不进入战斗房。
  - 地图刷新后对应精英节点通关。
  - 下一个诊断节点解锁。
- 诊断未全对：
  - 自动进入绑定精英关卡。
  - URL 或内部 `nodeId` 已切换为精英节点。
  - 精英关卡结束后显示精英正确率。
  - AI 诊断使用精英答题记录。
- 空记录异常：
  - 不显示 AI 伪诊断。
  - 显示明确失败态。

## 八、执行顺序

1. 后端先改 `diagnoseNode` 流程，明确诊断节点与精英节点绑定关系。
2. 前端改 `FloorView.vue`，取消诊断节点本地切战斗房，改为按后端返回跳转精英节点。
3. 前端改 `DiagnosisRoom.vue`，删除“直接进入战斗”，补全诊断记录结构。
4. 前端改 `BattleRoom.vue`，区分 `elite_room/battle_room/boss_room` 的答题记录来源。
5. 后端改 `completeNode` AI 输入校验和精英正确率复算。
6. 增加后端单测。
7. 跑 `npm run build` 和 Maven 定向测试。
8. 手动验证诊断全对、诊断未全对、空记录失败三条主路径。

## 九、验收标准

- 诊断房不再有自己单独的战斗房。
- 诊断全对会直接跳过并通关绑定精英关卡。
- 诊断未全对会自动进入绑定精英关卡。
- 精英结算正确率只来自精英关卡答题记录。
- AI 诊断报告只在精英关卡结束后生成。
- `answerSummary` 为空或无效时，后端不调用 AI，并返回明确失败态。
- 前端不再展示“未检测到答题记录”这种被当成 AI 诊断方案的内容。
- 加载中、成功、失败状态清晰可见，页面不会长时间停在降级或伪诊断内容上。
