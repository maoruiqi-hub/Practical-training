# Feature Specification: 爬塔错题商店（鸿蒙学生端）

**Created**: 2026-07-02  
**Status**: Draft  
**Input**: 基于已有 Spring Boot 后端 + Vue 前端的"爬塔学习"系统，选取"错题商店"节点，在鸿蒙端实现学生从登录到使用商店的完整交互链路。

## Overview

学生登录爬塔学习系统后，通过学生首页进入爬塔地图，在爬塔路线上遇到"错题商店"节点时可以进入商店页面。商店展示该学生的错题列表和当前金币余额，学生可使用金币执行两种操作：**购买提示卡**（消耗 10 金币，为后续战斗获取攻击准备）或**净化错题卡**（消耗 8 金币，将错题转化为防御和经验收益）。

本功能是爬塔学习系统中"学生端鸿蒙切片"的核心验证模块——它证明了鸿蒙端可以复用已有后端 API，完成从登录、画像展示、地图导航到具体节点交互的完整端到端链路。

## User Scenarios & Testing

### User Story 1 - 学生登录并进入爬塔 (Priority: P1)

学生打开鸿蒙 App，输入后端地址、账号和密码，点击登录。登录成功后跳转到学生首页，看到自己的游戏画像（HP、攻击力、防御力、经验值、金币），点击"进入爬塔"按钮进入爬塔地图页。

**Why this priority**: 登录是入口，无登录则无法访问任何后续功能；首页画像展示是学生对自身游戏状态的第一次感知。

**Independent Test**: 可以独立测试——输入有效的账号密码 → 看到首页画像数据 → 点击"进入爬塔"看到地图。

**Acceptance Scenarios**:

1. **Given** App 刚启动，**When** 学生输入正确的后端地址、账号、密码并点击登录，**Then** 跳转到学生首页，页面显示欢迎语和画像面板（包含 HP、ATK、DEF、EXP、Coins 数值）。
2. **Given** App 刚启动，**When** 学生输入错误的账号或密码，**Then** 页面显示"登录请求失败"提示，停留在登录页。
3. **Given** 学生已成功登录，**When** 点击"进入爬塔"按钮，**Then** 跳转到爬塔地图页，显示楼层节点列表。

---

### User Story 2 - 查看爬塔地图并定位商店节点 (Priority: P2)

学生在爬塔地图页可以看到按楼层排列的节点卡片列表。每个节点显示节点名称、楼层号和房间类型。不同类型的节点有不同的视觉区分，其中"商店"节点可点击进入。

**Why this priority**: 地图是爬塔的核心导航界面，学生需要在此页面找到商店节点并进入。

**Independent Test**: 已登录状态下，直接访问爬塔地图页 → 看到节点列表 → 找到标记为"商店"的节点。

**Acceptance Scenarios**:

1. **Given** 学生已在首页，**When** 进入爬塔地图页，**Then** 页面顶部显示画像面板（HP/ATK/DEF/EXP/Coins），下方滚动列表显示各楼层节点。
2. **Given** 爬塔地图已加载，**When** 学生查看节点列表，**Then** 每种节点类型有明确的文字标签区分（诊断/战斗/精英/Boss/宝箱/商店/休息/事件），商店节点颜色突出，可点击。
3. **Given** 爬塔地图已加载，**When** 学生点击非商店节点（如战斗、Boss），**Then** 节点无响应或显示"该节点暂未开放"。

---

### User Story 3 - 进入错题商店并执行操作 (Priority: P3)

学生点击商店节点后进入错题商店页。页面顶部显示当前金币余额，中间列表展示该学生的错题（最多 5 条，包含题号和题目内容）。底部有两个操作按钮：**"购买提示卡"**（消耗 10 金币）和**"净化错题卡"**（消耗 8 金币）。金币不足时对应按钮置灰。操作成功后按钮变灰并显示"已完成"。

**Why this priority**: 这是本功能的最终价值交付——学生通过商店节点消耗游戏资源换取学习辅助。

**Independent Test**: 已登录且地图已加载，点击商店节点 → 看到错题列表和金币余额 → 执行购买/净化操作 → 看到操作结果反馈。

**Acceptance Scenarios**:

1. **Given** 学生进入错题商店页，**When** 页面加载完成，**Then** 页面顶部显示"金币：XX"，中间显示错题列表（标题 + 题目内容，最多 5 条），底部显示"购买提示卡"和"净化错题卡"两个按钮。
2. **Given** 学生金币 ≥ 10，**When** 点击"购买提示卡"，**Then** 按钮变为"已完成"，系统向后端发送 shop_purchased 事件。
3. **Given** 学生金币 < 10，**When** 查看"购买提示卡"按钮，**Then** 按钮置灰不可点击。
4. **Given** 学生金币 ≥ 8 且有错题，**When** 点击"净化错题卡"，**Then** 按钮变为"已完成"，系统向后端发送 shop_purchased 事件。
5. **Given** 学生无错题记录，**When** 进入错题商店页，**Then** 错题列表显示"暂无错题卡"空状态，"净化错题卡"按钮置灰。

---

### Edge Cases

- 后端服务不可用时，所有 API 请求返回友好错误提示，不白屏不崩溃。
- 登录 Cookie 过期后，后续请求失败时给出明确提示（而非静默失败）。
- 错题列表超过 5 条时，只展示前 5 条。
- 学生在商店页操作成功、返回地图后再次进入同一商店节点，按钮应保持"已完成"状态（至少在当前 Session 内）。
- 金币余额为 0 时，两个操作按钮均置灰。

## Requirements

### Functional Requirements

- **FR-001**: 系统必须提供登录页，包含后端地址、账号、密码三个输入框和登录按钮。
- **FR-002**: 系统必须在登录成功后保存 Session Cookie，并在后续所有 API 请求中自动携带。
- **FR-003**: 系统必须提供学生首页，展示欢迎语和画像面板（HP、ATK、DEF、EXP、Coins），以及"进入爬塔"按钮。
- **FR-004**: 画像面板必须作为可复用组件，在首页和爬塔地图页均能渲染。
- **FR-005**: 系统必须提供爬塔地图页，从后端获取楼层节点数据并以列表形式展示。
- **FR-006**: 爬塔地图页中的每个节点必须显示节点名称、楼层号、房间类型标签。
- **FR-007**: 商店节点（roomType === 'shop'）必须可点击进入错题商店页。
- **FR-008**: 非商店节点在现阶段不可点击（或点击后提示"暂未开放"）。
- **FR-009**: 错题商店页必须从后端获取学生错题列表并展示（题号 + 题目内容，最多 5 条）。
- **FR-010**: 错题商店页必须展示当前金币余额。
- **FR-011**: 错题商店页必须提供"购买提示卡"按钮，消耗 10 金币，金币不足时置灰。
- **FR-012**: 错题商店页必须提供"净化错题卡"按钮，消耗 8 金币，金币不足或无错题时置灰。
- **FR-013**: 操作成功后必须向后端发送 game-event（event_type: "shop_purchased"），并在 UI 上反馈操作结果。
- **FR-014**: 所有 API 请求失败时必须显示友好错误提示，不白屏、不崩溃。
- **FR-015**: 系统必须使用 Navigation + NavPathStack 实现页面跳转，支持返回上一页。

### Key Entities

- **学生画像 (StudentProfile)**：包含昵称、等级、HP（当前/最大值）、攻击力(ATK)、防御力(DEF)、经验值(EXP)、金币(Coins)、精力等游戏属性。
- **爬塔节点 (TowerNode)**：属于某个楼层，有节点名称、房间类型（诊断/战斗/精英/Boss/宝箱/商店/休息/事件）、状态（锁定/解锁/完成）等属性。
- **错题记录 (MistakeItem)**：学生答错的题目，包含题号、题目题干、关联知识点等信息。
- **商店操作 (ShopAction)**："购买提示卡"或"净化错题卡"，消耗金币，生成游戏事件。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 学生从打开 App 到完成登录并看到首页画像，整个过程不超过 10 秒（在正常网络条件下）。
- **SC-002**: 爬塔地图页在 API 返回后 2 秒内完成节点列表渲染。
- **SC-003**: 错题商店页在 API 返回后 1 秒内展示错题列表和金币余额。
- **SC-004**: 学生执行"购买提示卡"或"净化错题卡"操作后，1 秒内收到操作结果反馈。
- **SC-005**: 所有页面在 API 请求失败时均有错误提示，无白屏或崩溃情况。
- **SC-006**: 页面之间的导航跳转流畅，支持返回操作且不丢失前页状态。

## Assumptions

- 后端 Spring Boot 服务已运行，且所有引用的 API 端点（登录、画像、爬塔地图、错题列表、游戏事件）均可正常响应。
- 后端使用 Session Cookie 进行身份认证，Cookie 由 Set-Cookie 响应头下发。
- 学生已通过 Web 端或其他方式在系统中注册了账号。
- 课程 ID（courseId）在登录时由学生手动输入。
- 网络环境为校园局域网，延迟在 500ms 以内。
- 鸿蒙设备为手机或平板，屏幕分辨率 ≥ 720×1280。
- 本功能为纯文字 UI，不使用图片或自定义图标资源。

## Open Questions

- 操作成功后是否需要刷新画像面板中的金币数值？当前默认：需要刷新。
- 购买提示卡/净化错题卡后是否需要关闭商店页返回地图？当前默认：不自动关闭，学生手动返回。
